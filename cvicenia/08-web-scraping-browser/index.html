Cvičenie 08Exercise 08

Web scraping a automatizácia prehliadačaWeb Scraping and Browser Automation

PrípravaSetup

Vytvorte prehľad univerzitných workshopov a konzultácií. Statické stránky tvoria viacstranový program podujatí; samostatná JavaScript stránka poskytuje dynamické vyhľadávanie. Pracujte výlučne s dodaným lokálnym webom, nie s produktovým katalógom z prednášky.Build an overview of university workshops and consultations. Static pages form a multipage event programme; a separate JavaScript page offers dynamic search. Use only the supplied local website, in a different domain from the lecture's product catalogue.

  • events/page1.html
  • events/page2.html
  • events/page3.html
  • dynamic/search.html
  • scraper_starter.py
  • README.md

CieleGoals

  • vyrobiť jeden model podujatia zo statického aj dynamického zdrojaproduce one event model from static and dynamic sources
  • rozlišovať neznámy údaj, zrušené podujatie a neplatnú kartudistinguish unknown data, cancelled events and invalid cards
  • overiť úplnosť zberu bez závislosti od cudzieho webuverify collection completeness without relying on an external site

ÚlohyTasks

Úloha 1 — Zmluva programu podujatíTask 1 — Event programme contract

Prezrite tri statické stránky v editore aj v prehliadači. Zatiaľ neimplementujte zber.Inspect the three static pages in an editor and browser before implementing collection.

  • Určte, čo predstavuje jednu kartu a kde sa nachádza identifikátor, názov, začiatok, miestnosť, kapacita, stav a detail URL.Identify one event card and locate its identifier, title, start time, room, capacity, status and detail URL.
  • Rozlíšte text a atribúty, navrhnite vlastné selektory a zapíšte ich spolu s odôvodnením.Distinguish text from attributes and document your own selectors with reasons.
  • Všimnite si časový offset, rovnaké podujatie na dvoch stránkach a rozdiel medzi zrušeným a chybným záznamom.Identify the time offset, an event repeated across pages and the difference between cancellation and invalid data.

Úloha 2 — Jeden platný záznamTask 2 — One valid record

Navrhnite vlastný pomenovaný Python model podujatia a parser jednej karty.Design a named Python event model and a single-card parser.

  • Výsledok obsahuje event_id, title, starts_at s časovým pásmom, room, capacity, status a absolútnu detail URL.Return event_id, title, timezone-aware starts_at, room, capacity, status and an absolute detail URL.
  • Chýbajúca miestnosť znamená neznámy údaj. Názov musí zachovať oddelenie slov aj pri vnorenom zvýraznení.A missing room is unknown. Preserve word boundaries in titles containing nested markup.
  • Na prvej platnej karte overte všetky polia. Parser nesmie sám odosielať request ani zapisovať výsledný export.Verify all fields on the first valid card. The parser must not send requests or write the final export.

Úloha 3 — Rozhodnutie o chybnej karteTask 3 — Invalid-card policy

Nie každý blok v programe podujatí je použiteľný záznam.Not every event block is a usable record.

  • Vyžadujte ID, názov, platný čas s offsetom, kladnú celočíselnú kapacitu, známy stav open/full/cancelled a HTTP detail URL.Require an ID, title, valid time with offset, positive integer capacity, status open/full/cancelled and an HTTP detail URL.
  • Neplatné karty odmietnite s dôvodom a identifikátorom, ak je dostupný. Zrušené podujatie je platné a zostáva v plnom zozname.Reject invalid cards with a reason and identifier when available. A cancelled event is valid and stays in the full list.
  • Zozbierajte samostatne počet kariet, prijatých výsledkov a odmietnutí; prázdny výsledok nesmie zakryť chybu vstupu.Track card count, accepted records and rejections separately; an empty result must not conceal an input failure.

Úloha 4 — Celý program bez slučkyTask 4 — Complete programme without loops

Prejdite program od events/page1.html podľa navigácie dokumentu.Traverse the programme from events/page1.html following document navigation.

  • Nenahradzujte navigáciu natvrdo vypísanými troma názvami súborov. Koniec určte z obsahu aktuálnej stránky.Do not replace navigation with three hardcoded filenames. Derive completion from the current document.
  • Zastavte opakovanú URL a prekročenie dohodnutého limitu stránok. Nepovoľte cestu mimo lokálneho testovacieho webu.Stop repeated URLs and the page limit. Reject targets outside the local test website.
  • Pri chybe ďalšej stránky označte zber za neúplný. Nezamieňajte to s úspešným koncom programu.Mark a failed subsequent page as incomplete collection, not successful completion.

Úloha 5 — Identita podujatia a konfliktyTask 5 — Event identity and conflicts

Rovnaké podujatie sa môže objaviť v dvoch častiach programu.The same event may appear in two parts of the programme.

  • Odstráňte identické opakovania podľa event_id a zachovajte deterministické poradie.Deduplicate identical event_id records while preserving deterministic order.
  • Ak dve karty s rovnakým ID uvádzajú rozdielny čas alebo názov, konflikt zaznamenajte a nevyberajte náhodnú verziu.Report conflicting times or titles for one ID rather than choosing an arbitrary version.
  • Pridajte vlastnú konfliktnú fixture a ukážte, že deduplikácia neodstráni dve rôzne udalosti v rovnakom čase.Add a conflicting fixture and show that two different simultaneous events are not deduplicated.

Úloha 6 — Výber užitočný pre študentaTask 6 — A useful student-facing selection

Z platného programu vytvorte denný a miestnostný prehľad.Produce day and room views of the valid programme.

  • Umožnite filter podľa dátumu a stavu. Základný výpis neobsahuje cancelled, ale plný export tieto podujatia zachová.Support date and status filters. Hide cancelled events in the default view but preserve them in the full export.
  • Zoraďte udalosti podľa skutočného času a pri zhode podľa ID; uveďte miestne časové pásmo výpisu.Sort by actual start time and break ties by ID; state the display time zone.
  • Nájdite súbežné podujatia v tej istej známej miestnosti a s rovnakým začiatkom. Neznáma miestnosť sa nesmie tváriť ako spoločná skutočná miestnosť.Find events with the same start time in the same known room. Unknown rooms must not be treated as one real shared room.

Úloha 7 — Lokálna HTTP vrstvaTask 7 — Local HTTP layer

Statické stránky teraz sťahujte cez lokálny server namiesto priameho čítania súborov.Fetch the static pages through the local server instead of reading files directly.

  • Rozlišujte úspešnú stránku, HTTP 404 a nedostupný server. Nastavte konečný timeout a maximálny rozsah zberu.Distinguish a valid page, HTTP 404 and an unavailable server. Set finite timeouts and collection bounds.
  • Opakujte rovnaký parser bez jeho úprav; pri čítaní súboru a HTTP musia vyjsť rovnaké normalizované podujatia.Reuse the unchanged parser; file and HTTP inputs must yield identical normalized events.
  • Do reportu zapíšte počet navštívených stránok a chyby. Zámerne vyskúšajte neexistujúcu stránku.Report visited-page count and failures. Deliberately test a nonexistent page.

Úloha 8 — Dynamické vyhľadávanieTask 8 — Dynamic event search

Na dynamic/search.html sa výsledky menia až po JavaScript interakcii.On dynamic/search.html, results change only after a JavaScript interaction.

  • Cez Playwright vyhľadajte Python a získajte údaje oboch nájdených podujatí, nie iba prvého viditeľného výsledku.Search for Python with Playwright and collect both matching events, not just the first visible result.
  • Zistite kontrakt dokončenia zo zdroja stránky. Nepridávajte pevnú časovú pauzu ako náhradu kontroly stavu.Identify the completion contract from the page source. Do not replace state checks with a fixed sleep.
  • Overte aj vyhľadávanie bez zhody a ďalšie vyhľadanie Git v tej istej session; staré výsledky sa nesmú pripočítať k novým.Also test no matches and a subsequent Git search in the same session; old results must not leak into the new set.

Úloha 9 — Testy parsera aj načítaniaTask 9 — Parser and loading tests

Overte pravidlá na malých kontrolovaných vstupoch, aby zmena stránky nespôsobila tichú chybu.Verify rules with small controlled inputs to prevent silent breakage after markup changes.

  • Napíšte aspoň päť testov: platný záznam, chýbajúca miestnosť, neplatný čas, chýbajúci detail a konfliktné ID.Write at least five tests: valid record, missing room, invalid time, missing detail and conflicting ID.
  • Parserové testy fungujú bez servera. Browserový test samostatne overuje dokončenie a prázdny výsledok.Parser tests run without a server. A separate browser test checks completion and no results.
  • Pri neúspešnom zbere uchovajte diagnostiku a posledný platný výstup. Žiadne cudzie weby nie sú potrebné.Preserve diagnostics and the last valid output when collection fails. No external websites are needed.

Úloha 10 — Jeden opakovateľný prehľadTask 10 — One reproducible overview

Spojte zber, normalizáciu, filtre a export do jedného nástroja.Combine collection, normalization, filters and export into one tool.

  • Vytvorte events.json a events.csv s rovnakými udalosťami, ISO časmi s offsetom a jasne definovanou neznámou miestnosťou.Produce events.json and events.csv with identical events, ISO times including offsets and an explicit unknown-room representation.
  • Pridajte CLI vstupnú adresu a filter dňa; pri neúplnom zbere vráťte neúspešný výsledok a neprepíšte platné dáta.Support a start URL and day filter through the CLI; incomplete collection must fail without overwriting valid data.
  • V README uveďte spustenie lokálneho servera, závislosti, testy, počty prijatých/odmietnutých/duplicitných kariet a obmedzenia.Document the local server, dependencies, tests, accepted/rejected/duplicate counts and limitations.

OdovzdanieDeliverables

  • Odovzdajte scraper, vlastné testovacie HTML fragmenty, testy a ukážkové exporty.Deliver the scraper, custom HTML fixtures, tests and sample exports.
  • Zdrojové HTML nemeňte tak, aby chyby zmizli; vaše doplnkové fixture patria do vlastného testovacieho priečinka.Do not edit source HTML to remove its edge cases; place additional fixtures in your own test directory.
