CieleGoals

  • písať testy pre existujúci kód, nie iba pre vlastné ideálne funkcie;
  • reprodukovať bug cez zlyhávajúci test;
  • použiť parametrizáciu, fixtures, exceptions a tmp_path;
  • kombinovať debugger, logging a Ruff pri oprave malej codebase.
  • write tests for existing code, not only for your own ideal functions;
  • reproduce a bug with a failing test;
  • use parametrization, fixtures, exceptions and tmp_path;
  • combine a debugger, logging and Ruff when fixing a small codebase.

Úloha 2 — Edge cases pred opravou implementácieTask 2 — Edge Cases Before Fixing Implementation

Funkcia calculate_discount(price, discount) potrebuje jasný kontrakt.

Najprv navrhnite testy pre tieto prípady:

  • price == 0;
  • discount == 0;
  • discount == 1;
  • discount < 0;
  • discount > 1;
  • negatívna cena.

Až potom upravte implementáciu. Neplatné hodnoty majú vyvolať ValueError.

The function calculate_discount(price, discount) needs a clear contract.

First design tests for these cases:

  • price == 0;
  • discount == 0;
  • discount == 1;
  • discount < 0;
  • discount > 1;
  • negative price.

Only then change the implementation. Invalid values should raise ValueError.

calculate_discount(100, 0)   -> 100
calculate_discount(100, 1)   -> 0
calculate_discount(100, -0.1) -> ValueError
calculate_discount(-5, 0.2)  -> ValueError

Pomôcka: Testy majú rozhodnúť, čo je povolené správanie. Implementáciu prispôsobte až po tom.

Hint: Tests should define the allowed behavior. Adapt the implementation only after that.

Úloha 3 — Parametrized testsTask 3 — Parametrized Tests

Podobné testy pre platné výpočty z úlohy 2 prepíšte cez pytest.mark.parametrize.

Rewrite similar tests for valid calculations from Task 2 using pytest.mark.parametrize.

import pytest


@pytest.mark.parametrize(
    "price, discount, expected",
    [
        (100, 0.0, 100),
        (100, 0.2, 80),
        (100, 1.0, 0),
        (59.9, 0.5, 29.95),
    ],
)
def test_valid_discounts(price, discount, expected):
    assert calculate_discount(price, discount) == pytest.approx(expected)

Pridajte ešte parametrizovaný test pre neplatné hodnoty. Použite minimálne štyri prípady.

Add another parametrized test for invalid values. Use at least four cases.

Vysvetlite jednou vetou, prečo sa pri float hodnotách používa pytest.approx().

Explain in one sentence why pytest.approx() is used for float values.

Úloha 4 — Exception contractTask 4 — Exception Contract

Otestujte funkciu validate_score(). Platné skóre vráti pôvodnú hodnotu, neplatné skóre vyvolá ValueError.

Test the function validate_score(). A valid score returns the original value; an invalid score raises ValueError.

with pytest.raises(ValueError):
    validate_score(-1)

Požadované test cases:

  • 0, 51, 100 sú platné hodnoty;
  • -1 a 101 sú neplatné hodnoty;
  • ak sa rozhodnete riešiť typy, string alebo None majú mať jasné správanie.

Test má kontrolovať výnimku, nie iba to, že program "nejako spadne".

Required test cases:

  • 0, 51, 100 are valid values;
  • -1 and 101 are invalid values;
  • if you decide to handle types, a string or None should have clearly defined behavior.

The test should check the exception, not only that the program "somehow crashes".

Úloha 5 — Fixtures a spoločné testovacie dátaTask 5 — Fixtures and Shared Test Data

Vytvorte testy pre funkciu final_grade(). Použite fixture alebo parametrizáciu tak, aby sa neopakovali rovnaké vstupné dáta vo viacerých testoch.

Otestujte hranice hodnotenia:

Create tests for the function final_grade(). Use a fixture or parametrization so the same input data is not repeated across multiple tests.

Test grading boundaries:

100 -> A
90  -> A or B depending on your chosen contract
80  -> B or C depending on your chosen contract
51  -> E
50  -> FX

Ak test odhalí nejasné správanie na hraniciach, najprv ho presne pomenujte a až potom upravte implementáciu.

If a test reveals unclear boundary behavior, name it precisely first and only then change the implementation.

Pomôcka: Pri hodnotení je často lepšie explicitne testovať hraničné body než iba "typické" hodnoty.

Hint: For grading, it is often better to explicitly test boundary values than only "typical" values.

Úloha 6 — Temporary filesystemTask 6 — Temporary Filesystem

Otestujte save_report(path: Path, content: str) -> None z modulu app/storage.py bez zápisu do reálneho pracovného adresára.

Požiadavky:

  • použite pytest fixture tmp_path;
  • overte, že súbor vznikol;
  • overte obsah súboru;
  • doplňte test pre zápis do podadresára, ktorý ešte neexistuje;
  • implementáciu upravte tak, aby vytvorila potrebné parent directories.

Test save_report(path: Path, content: str) -> None from app/storage.py without writing into your real working directory.

Requirements:

  • use the pytest fixture tmp_path;
  • verify that the file was created;
  • verify the file contents;
  • add a test for writing into a subdirectory that does not exist yet;
  • adjust the implementation so it creates the required parent directories.
def test_save_report_creates_file(tmp_path):
    output = tmp_path / "reports" / "summary.txt"

    save_report(output, "OK")

    assert output.read_text(encoding="utf-8") == "OK"

Ak test zlyhá pre encoding, upravte implementáciu tak, aby používala encoding="utf-8".

If the test fails because of encoding, adjust the implementation to use encoding="utf-8".

Úloha 7 — Regression bug v textových štatistikáchTask 7 — Regression Bug in Text Statistics

V app/text_stats.py je chyba pri počítaní slov a riadkov.

Najprv vytvorte testy pre:

  • prázdny text;
  • text s viacerými medzerami;
  • text s newline znakmi;
  • text, ktorý končí newline znakom;
  • text s tabulátorom.

There is a bug in app/text_stats.py when counting words and lines.

First create tests for:

  • empty text;
  • text with multiple spaces;
  • text with newline characters;
  • text ending with a newline character;
  • text with a tab character.
""                   -> words=0, lines=0
"Anna  Peter"        -> words=2
"one\ntwo\nthree"    -> lines=3
"one\n"              -> lines=1

Postup: napíšte zlyhávajúci test, spustite ho, opravte implementáciu, spustite celý test suite.

Procedure: write a failing test, run it, fix the implementation and run the whole test suite.

Regression test je test pridaný po nájdení chyby, aby sa rovnaká chyba nevrátila.

A regression test is a test added after finding a bug so the same bug does not return later.

Úloha 8 — Debugging namiesto hádaniaTask 8 — Debugging Instead of Guessing

Vyberte jednu z chýb vo funkciách final_grade() alebo analyze_text() a nájdite ju cez debugger.

Postup:

  • nastavte breakpoint na začiatok funkcie;
  • spustite konkrétny zlyhávajúci test v debug režime;
  • sledujte hodnoty vstupov a lokálnych premenných;
  • krokujte cez podmienky;
  • zapíšte, ktorý riadok spôsoboval nesprávne správanie.

Potom pridajte do vhodného miesta logging, ktorý by pri reálnom použití pomohol problém diagnostikovať.

Choose one bug in final_grade() or analyze_text() and find it with a debugger.

Procedure:

  • set a breakpoint at the start of the function;
  • run the specific failing test in debug mode;
  • inspect input values and local variables;
  • step through conditions;
  • write down which line caused the incorrect behavior.

Then add logging at a suitable place that would help diagnose the problem in real use.

import logging

logger = logging.getLogger(__name__)

logger.warning("Invalid score received: %s", score)

Logging nemá nahradiť test. Má pomôcť pri pochopení správania programu počas behu.

Logging should not replace a test. It should help understand program behavior at runtime.

Úloha 9 — Ruff a čitateľnosťTask 9 — Ruff and Readability

Spustite Ruff nad starter projektom.

Run Ruff on the starter project.

ruff check .
ruff format .

Opravte nájdené problémy tak, aby sa nezmenilo správanie programu. Pri každej úprave rozlišujte:

  • lint problém, ktorý vie nástroj spoľahlivo nájsť;
  • formátovanie, ktoré vie nástroj upraviť automaticky;
  • logickú chybu, ktorú musí pokryť test.

Fix the reported issues without changing program behavior. For every change, distinguish between:

  • a lint issue that the tool can reliably find;
  • formatting that the tool can adjust automatically;
  • a logic bug that must be covered by a test.
All checks passed!

Po formátovaní znovu spustite python -m pytest. Čistý Ruff výstup neznamená, že program funguje správne.

After formatting, run python -m pytest again. A clean Ruff result does not mean the program works correctly.

Úloha 10 — Integračná oprava starter projektuTask 10 — Integrated Starter Project Fix

Upravte starter projekt tak, aby mal zmysluplný test suite a opravené hlavné chyby.

Minimálne požiadavky:

  • testy pre calculate_discount() vrátane neplatných vstupov;
  • testy pre hranice final_grade();
  • regression testy pre analyze_text();
  • testy pre save_report() s tmp_path;
  • jeden test s nahradenou dependency vo funkcii price_in_eur();
  • opravený kód bez tichého ignorovania chýb;
  • prechádzajúce pytest aj ruff check ..

Modify the starter project so it has a meaningful test suite and the main bugs are fixed.

Minimum requirements:

  • tests for calculate_discount(), including invalid inputs;
  • tests for final_grade() boundaries;
  • regression tests for analyze_text();
  • tests for save_report() with tmp_path;
  • one test with a replaced dependency in price_in_eur();
  • fixed code without silently ignored errors;
  • passing pytest and ruff check ..
def test_price_in_eur_uses_exchange_rate(monkeypatch):
    monkeypatch.setattr("app.pricing.get_exchange_rate", lambda: 0.92)

    assert price_in_eur(100) == 92
$ python -m pytest

$ ruff check .
All checks passed!

Výsledkom nemá byť veľká architektúra. Stačí malý projekt, ktorého správanie je presne popísané testami.

The result should not be a large architecture. A small project whose behavior is precisely described by tests is enough.
