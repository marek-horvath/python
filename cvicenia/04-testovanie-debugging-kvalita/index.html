Testovanie, debugging a kvalita kóduTesting, Debugging and Code Quality

PrípravaSetup

Stiahnite starter ZIP a rozbaľte ho do pracovného adresára. Projekt je kalkulačka ceny zásielok s úmyselnými chybami. Nepoužíva GUI ani TODO zoznam z prednášky.

Download and extract the starter ZIP into a working directory. The project is a parcel price calculator with intentional defects. It does not reuse the GUI or TODO list from the lecture.

Stiahnuť starter ZIPDownload starter ZIP

cd exercise-04
python -m unittest discover -s tests -v

Používajte iba štandardnú knižnicu Pythonu. Testy píšte cez unittest.

Use only the Python standard library. Write tests with unittest.

KontextContext

Vstupný riadok opisuje jednu zásielku vo formátereferencia;zóna;hmotnosť;express. Aplikácia ho parsuje, vypočíta cenu, spracuje dávku zásielok a uloží report. Starter obsahuje chyby v každej z týchto vrstiev.

One input line describes a parcel as reference;zone;weight;express. The application parses it, calculates a price, processes a batch and saves a report. The starter contains defects in each of these layers.

PK-001;SK;2.5;no
PK-002;EU;0.8;yes

ÚlohyTasks

Úloha 1 — Reprodukovateľný bug reportTask 1 — Reproducible Bug Report

Prejdite súbory v app/ a ručne zavolajte parse_shipment() s týmto vstupom:

PK-001;SK;2.5;no

Zapíšte krátky bug report obsahujúci vstup, presný postup, expected výsledok a actual výsledok. Zatiaľ kód neopravujte.

Inspect the files in app/ and call parse_shipment() manually with this input:

PK-001;SK;2.5;no

Write a short bug report with the input, exact steps, expected result and actual result. Do not fix the code yet.

Úloha 2 — Prvý zlyhávajúci testTask 2 — First Failing Test

Vytvorte tests/test_parser.py a test zachytávajúci chybu z úlohy 1.

  • test musí byť metóda triedy odvodenej od unittest.TestCase;
  • najprv overte, že na pôvodnej implementácii zlyhá;
  • urobte najmenšiu potrebnú opravu a spustite ten istý test znova;
  • názov testu má opisovať správanie, nie názov riadku v kóde.

Create tests/test_parser.py and a test that captures the bug from Task 1.

  • the test must be a method of a unittest.TestCase subclass;
  • first confirm that it fails against the original implementation;
  • make the smallest necessary fix and run the same test again;
  • the test name should describe behaviour, not a source-code line.

Úloha 3 — Kontrakt parseraTask 3 — Parser Contract

Doplňte testy a implementáciu parse_shipment() podľa kontraktu:

  • riadok musí obsahovať presne štyri polia oddelené bodkočiarkou;
  • medzery okolo polí sa ignorujú a zóna sa normalizuje na veľké písmená;
  • yes a no sa spracujú bez ohľadu na veľkosť písmen;
  • prázdna referencia, nečíselná hmotnosť alebo iná express hodnota vyvolá ValueError.

Navrhnite aspoň päť test cases. Nezlučujte odlišné dôvody zlyhania do jedného nečitateľného testu.

Add tests and implement parse_shipment() according to this contract:

  • a line must contain exactly four semicolon-separated fields;
  • surrounding whitespace is ignored and the zone is normalised to uppercase;
  • yes and no are case-insensitive;
  • an empty reference, non-numeric weight or another express value raises ValueError.

Design at least five test cases. Do not combine unrelated failure reasons into one unreadable test.

Úloha 4 — Hranice ceny zásielkyTask 4 — Parcel Price Boundaries

Otestujte shipping_price(weight_kg, zone, express). Cenník je:

základ: SK = 2.50 €, EU = 5.00 €
0 < hmotnosť <= 1 kg       príplatok 0.00 €
1 < hmotnosť <= 5 kg       príplatok 2.00 €
5 < hmotnosť <= 20 kg      príplatok 5.00 €
express                    výsledok × 1.5

Pokryte hodnoty tesne pod hranicou, presne na hranici a tesne nad ňou. Výsledok sa zaokrúhľuje na dve desatinné miesta.

Test shipping_price(weight_kg, zone, express). The tariff is:

base: SK = 2.50 €, EU = 5.00 €
0 < weight <= 1 kg         surcharge 0.00 €
1 < weight <= 5 kg         surcharge 2.00 €
5 < weight <= 20 kg        surcharge 5.00 €
express                    result × 1.5

Cover values just below, exactly on and just above each boundary. Round the result to two decimal places.

Úloha 5 — Neplatné vstupy a výnimkyTask 5 — Invalid Inputs and Exceptions

Neplatná hmotnosť je 0, záporná hodnota alebo hodnota nad 20 kg. Povolené zóny sú iba SK a EU.

Napíšte testy, ktoré kontrolujú konkrétny typ výnimky. Upravte implementáciu tak, aby všetky porušenia verejného kontraktu vyvolali ValueError, nie náhodnú internú výnimku.

An invalid weight is 0, a negative value or a value above 20 kg. Only SK and EU are valid zones.

Write tests that check the specific exception type. Adjust the implementation so every public-contract violation raises ValueError, not an accidental internal exception.

Úloha 6 — Dávka zásielok a izolácia testovTask 6 — Parcel Batch and Test Isolation

Otestujte batch_total(shipments) pre prázdny zoznam, jednu zásielku a kombinovanú dávku.

  • spoločné vstupné dáta pripravujte v setUp();
  • každý test musí dostať nový mutable zoznam;
  • funkcia nesmie meniť poradie ani obsah vstupného zoznamu;
  • celková cena sa zaokrúhli na dve desatinné miesta.

Test batch_total(shipments) for an empty list, one parcel and a mixed batch.

  • prepare shared input data in setUp();
  • every test must receive a fresh mutable list;
  • the function must not change the input list's order or contents;
  • round the total to two decimal places.

Úloha 7 — Najdrahšia zásielkaTask 7 — Most Expensive Parcel

Funkcia most_expensive(shipments) má vrátiť zásielku s najvyššou cenou.

  • pre prázdny vstup vráti None;
  • pri rovnakej cene vráti prvú zásielku v pôvodnom poradí;
  • vstupný zoznam zostane nezmenený.

Najprv napíšte test pre prázdny vstup a potvrďte pôvodnú chybu. Tento test ponechajte ako regression test.

most_expensive(shipments) should return the parcel with the highest price.

  • return None for empty input;
  • when prices tie, return the first parcel in the original order;
  • leave the input list unchanged.

Write the empty-input test first and confirm the original defect. Keep this test as a regression test.

Úloha 8 — Debugger nad viacriadkovým vstupomTask 8 — Debugging Multi-line Input

Funkcia load_shipments(lines) má ignorovať prázdne riadky, ale nesmie potichu zahodiť neplatný neprázdny riadok.

Spustite ju s dátami nižšie, zastavte program cez breakpoint() a zistite, ktorý riadok sa posiela do parsera. Do poznámky k riešeniu zapíšte pozorovanú hodnotu a príčinu chyby. Potom pridajte regression test a opravte implementáciu.

load_shipments(lines) should ignore blank lines but must not silently discard an invalid non-blank line.

Run it with the data below, pause with breakpoint() and determine which line reaches the parser. Record the observed value and root cause in your solution notes. Then add a regression test and fix the implementation.

PK-001;SK;2.5;no

␠␠␠
PK-002;EU;0.8;yes

Úloha 9 — Report v dočasnom adresáriTask 9 — Report in a Temporary Directory

Otestujte render_report() a save_report() bez zápisu do repozitára.

  • použite tempfile.TemporaryDirectory;
  • cieľ umiestnite do zatiaľ neexistujúceho podadresára;
  • overte existenciu aj presný UTF-8 obsah súboru;
  • report musí obsahovať počet zásielok, celkovú cenu a referenciu najdrahšej zásielky;
  • prázdna dávka musí mať zrozumiteľný report.

Test render_report() and save_report() without writing into the repository.

  • use tempfile.TemporaryDirectory;
  • place the target inside a subdirectory that does not exist yet;
  • verify both file existence and exact UTF-8 contents;
  • the report must contain parcel count, total price and the most expensive parcel reference;
  • an empty batch must still produce an understandable report.

Úloha 10 — Integračný scenár a záverečná kontrolaTask 10 — Integration Scenario and Final Check

V jednom integračnom teste prepojte načítanie troch riadkov, výpočet dávky, výber najdrahšej zásielky, vytvorenie reportu a jeho uloženie.

Hotový projekt musí spĺňať:

  • minimálne 15 zmysluplných testov;
  • aspoň jeden test pre každú verejnú funkciu;
  • bežné, hraničné, chybové a regresné prípady;
  • žiadne except: pass ani testy závislé od poradia spustenia;
  • všetky testy prejdú aj pri opakovanom spustení celej sady.

In one integration test, connect loading three lines, calculating the batch, selecting the most expensive parcel, rendering the report and saving it.

The completed project must have:

  • at least 15 meaningful tests;
  • at least one test for every public function;
  • normal, boundary, error and regression cases;
  • no except: pass and no tests that depend on execution order;
  • all tests passing across repeated full-suite runs.
