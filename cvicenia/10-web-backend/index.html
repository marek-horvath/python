PrípravaSetup

V tomto cvičení vytvoríte malé REST API bez frontendu. Doména je jednoduchá: Notes API. Dôležité nie je množstvo endpointov, ale jasný kontrakt, validácia, správne status kódy, databáza a testovateľnosť.

Starter súbory: exercises/exercise-10/
Aplikácia: FastAPI + Pydantic + SQLAlchemy + SQLite
Výstup: funkčné CRUD API, testy a stručné README spustenia

Starter súbory sú dostupné aj ako ZIP archív.

In this exercise you will create a small REST API without a frontend. The domain is simple: Notes API. The important part is not the number of endpoints, but a clear contract, validation, correct status codes, database use and testability.

Starter files: exercises/exercise-10/
Application: FastAPI + Pydantic + SQLAlchemy + SQLite
Output: working CRUD API, tests and a short README for running it

Starter files are also available as a ZIP archive.

python -m pip install fastapi uvicorn sqlalchemy pytest httpx
uvicorn main:app --reload

CieleGoals

  • navrhnúť a implementovať malé REST API vo FastAPI;
  • použiť Pydantic modely na validáciu vstupu a tvar odpovede;
  • prepojiť endpointy so SQLite databázou cez SQLAlchemy;
  • napísať základné API testy a overiť chybové stavy.
  • design and implement a small REST API in FastAPI;
  • use Pydantic models for input validation and response shape;
  • connect endpoints to a SQLite database through SQLAlchemy;
  • write basic API tests and verify error states.

Úloha 2 — API kontrakt pre poznámkyTask 2 — API Contract for Notes

Upravte alebo skontrolujte Pydantic modely v schemas.py.

Požiadavky:

  • NoteCreate: povinný title, voliteľný body;
  • NoteUpdate: voliteľný title aj body;
  • NoteResponse: id, title, body;
  • title nesmie byť prázdny a má mať rozumnú maximálnu dĺžku;
  • request model a response model nemajú byť ten istý objekt bez rozmyslu.

Adjust or review Pydantic models in schemas.py.

Requirements:

  • NoteCreate: required title, optional body;
  • NoteUpdate: optional title and body;
  • NoteResponse: id, title, body;
  • title must not be empty and should have a reasonable maximum length;
  • request model and response model should not be the same object without a reason.
class NoteCreate(BaseModel):
    title: str = Field(min_length=1, max_length=120)
    body: str | None = None

V /docs overte, že OpenAPI schema zodpovedá modelom.

In /docs, verify that the OpenAPI schema matches the models.

Úloha 3 — List a detail endpointTask 3 — List and Detail Endpoint

Doplňte endpointy GET /items a GET /items/{item_id}.

Požiadavky:

  • GET /items vráti zoznam poznámok;
  • query parameter limit obmedzí počet výsledkov;
  • limit má byť validovaný, napríklad 1 až 100;
  • GET /items/{item_id} vráti jednu poznámku;
  • neexistujúce ID vráti 404.
GET /items?limit=2
200 OK
[
  {"id": 1, "title": "Prvá poznámka", "body": "Text"}
]

Neexistujúce ID nie je prázdny úspešný výsledok. Je to chybový stav klienta.

Add endpoints GET /items and GET /items/{item_id}.

Requirements:

  • GET /items returns a list of notes;
  • query parameter limit limits the number of results;
  • limit should be validated, for example from 1 to 100;
  • GET /items/{item_id} returns one note;
  • a non-existing ID returns 404.
GET /items?limit=2
200 OK
[
  {"id": 1, "title": "First note", "body": "Text"}
]

A non-existing ID is not an empty successful result. It is a client error state.

Úloha 4 — Create endpoint a databázový zápisTask 4 — Create Endpoint and Database Write

Doplňte POST /items, aby vytvoril novú poznámku v databáze.

Požiadavky:

  • použite SQLAlchemy model Note;
  • uložte objekt cez session;
  • po uložení vráťte objekt s prideleným id;
  • úspešné vytvorenie má vrátiť 201 Created;
  • duplicitný title ošetrite vhodnou chybou, napríklad 409 Conflict.
POST /items
{
  "title": "Poznámka k API",
  "body": "Endpointy majú vracať správne status kódy."
}
201 Created
{
  "id": 1,
  "title": "Poznámka k API",
  "body": "Endpointy majú vracať správne status kódy."
}

Add POST /items so it creates a new note in the database.

Requirements:

  • use the SQLAlchemy model Note;
  • save the object through a session;
  • after saving, return the object with the assigned id;
  • successful creation should return 201 Created;
  • handle duplicate title with a suitable error, for example 409 Conflict.
POST /items
{
  "title": "API note",
  "body": "Endpoints should return correct status codes."
}
201 Created
{
  "id": 1,
  "title": "API note",
  "body": "Endpoints should return correct status codes."
}

Úloha 5 — Update a delete endpointTask 5 — Update and Delete Endpoint

Doplňte PATCH /items/{item_id} a DELETE /items/{item_id}.

Požiadavky pre update:

  • umožniť zmeniť iba title, iba body alebo obe hodnoty;
  • hodnoty, ktoré neprišli v requeste, ponechať bez zmeny;
  • neexistujúce ID vráti 404;
  • duplicitný title vráti zrozumiteľnú chybu.

Požiadavky pre delete:

  • existujúcu poznámku odstrániť;
  • vrátiť 204 No Content;
  • po odstránení má detail toho ID vrátiť 404.

Add PATCH /items/{item_id} and DELETE /items/{item_id}.

Update requirements:

  • allow changing only title, only body or both values;
  • keep values that were not sent in the request unchanged;
  • a non-existing ID returns 404;
  • duplicate title returns a readable error.

Delete requirements:

  • delete an existing note;
  • return 204 No Content;
  • after deletion, detail for that ID should return 404.
PATCH /items/1 -> 200 OK
DELETE /items/1 -> 204 No Content
GET /items/1 -> 404 Not Found

Úloha 6 — Query parameters a filtrovanieTask 6 — Query Parameters and Filtering

Rozšírte GET /items o praktické query parametre.

Implementujte aspoň:

  • limit: počet výsledkov, validovaný rozsah;
  • offset: preskočenie prvých výsledkov;
  • q: jednoduché vyhľadávanie v title alebo body;
  • sort: napríklad id, title alebo -id.

Extend GET /items with practical query parameters.

Implement at least:

  • limit: number of results, validated range;
  • offset: skip the first results;
  • q: simple search in title or body;
  • sort: for example id, title or -id.
GET /items?q=api&limit=10&offset=0&sort=-id

Neplatný parameter, napríklad nepodporovaný sort field, má vrátiť vhodnú chybu, nie ignorovaný výsledok.

An invalid parameter, for example an unsupported sort field, should return a suitable error, not an ignored result.

Úloha 7 — Error handling a status kódyTask 7 — Error Handling and Status Codes

Prejdite API a zjednoťte chybové správanie.

Overte minimálne tieto prípady:

  • neexistujúce ID → 404 Not Found;
  • duplicitný title → 409 Conflict;
  • nevalidný request body → validačná odpoveď FastAPI/Pydantic;
  • neplatný query parameter → 400 Bad Request alebo validačná chyba;
  • nečakaná chyba databázy nemá odhaliť interné detaily používateľovi.

Review the API and unify error behavior.

Verify at least these cases:

  • non-existing ID → 404 Not Found;
  • duplicate title → 409 Conflict;
  • invalid request body → FastAPI/Pydantic validation response;
  • invalid query parameter → 400 Bad Request or a validation error;
  • an unexpected database error must not reveal internal details to the user.
HTTP/1.1 404 Not Found
{
  "detail": "Item not found"
}

Nepoužívajte 200 OK pre situácie, kde klient žiada neexistujúci alebo nevalidný zdroj.

Do not use 200 OK for situations where the client requests a non-existing or invalid resource.

Úloha 8 — Testovateľná databázaTask 8 — Testable Database

Pripravte API tak, aby sa dalo testovať bez zapisovania do vašej bežnej notes.db.

Možnosti:

  • použiť DATABASE_URL z environment variable;
  • v testoch nastaviť dočasnú SQLite databázu;
  • alebo vo FastAPI testoch použiť dependency override pre get_session.

Prepare the API so it can be tested without writing into your regular notes.db.

Options:

  • use DATABASE_URL from an environment variable;
  • set a temporary SQLite database in tests;
  • or use a dependency override for get_session in FastAPI tests.
DATABASE_URL=sqlite:///test_notes.db python -m pytest

Výsledok testov nesmie závisieť od poznámok, ktoré ste manuálne vytvorili cez browser alebo /docs.

Test results must not depend on notes that you manually created through a browser or /docs.

Napíšte minimálne testy pre:

  • zoznam poznámok;

  • delete poznámky;
  • duplicitný title;
  • filtrovanie cez q alebo limit.

Add test_api.py using TestClient.

Write at least tests for:

  • GET /;
  • creating a note;
  • listing notes;
  • detail of an existing note;
  • detail of a non-existing note;
  • invalid request body;
  • updating a note;
  • deleting a note;

python -m pytest

Testy majú overovať správanie API, nie iba to, že endpoint vôbec vrátil nejakú odpoveď.

Tests should verify API behavior, not only that an endpoint returned some response.

Dokončite projekt tak, aby bol spustiteľný aj pre niekoho iného.

Finálny stav má obsahovať:

  • CRUD endpointy pre poznámky;
  • Pydantic modely pre request a response;
  • SQLite/SQLAlchemy persistenciu;
  • query parametre pre list endpoint;
  • správne status kódy a chybové správy;

  • konfiguráciu databázy cez DATABASE_URL;

Finish the project so it can be run by someone else as well.

The final state should include:

  • CRUD endpoints for notes;
  • Pydantic models for request and response;
  • SQLite/SQLAlchemy persistence;
  • query parameters for the list endpoint;
  • correct status codes and error messages;
  • tests runnable with python -m pytest;
  • database configuration through DATABASE_URL;
  • README with installation, running, tests and request examples.

Do not create a frontend. The goal is a clean small backend API with a good contract.
