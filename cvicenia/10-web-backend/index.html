PrípravaSetup

Vytvorte Notes API pre osobné pracovné poznámky. Oproti rezerváciám z prednášky riešte jedinečné názvy, archív, vyhľadávanie a význam čiastočnej úpravy. Štartovací projekt poskytuje infraštruktúru a nehotové endpointy, nie implementované CRUD riešenie. Frontend ani prihlasovanie v tomto lokálnom cvičení netvorte.Build a Notes API for personal working notes. Unlike the lecture's reservations, handle unique titles, archiving, search and partial-update semantics. The starter supplies infrastructure and unfinished endpoints, not a CRUD solution. No frontend or authentication is required for this local exercise.

CieleGoals

  • implementovať verejný kontrakt namiesto kopírovania rezervačných endpointovimplement a public contract rather than copying reservation endpoints
  • rozlišovať chýbajúce pole, null, prázdny text a konflikt názvudistinguish omitted fields, null, blank text and title conflicts
  • overiť uloženie aj izoláciu testovacej databázyverify persistence and test-database isolation

ÚlohyTasks

Úloha 1 — Preberte kontrakt a nehotový projektTask 1 — Inspect the contract and starter

Spustite projekt a zistite, ktoré endpointy sú len zámerne neimplementované.Run the project and identify deliberately unimplemented endpoints.

  • GET / vracia 200 a message Notes API. Ostatné routy na začiatku vracajú 501, nie falošný úspešný prázdny výsledok.GET / returns 200 with message Notes API. Other starter routes return 501 rather than a misleading empty success.
  • V api_contract.md opíšte GET/POST /items a GET/PATCH/DELETE /items/{id}, vstup a statusy 200, 201, 204, 404, 409 a 422.Document GET/POST /items and GET/PATCH/DELETE /items/{id}, inputs and statuses 200, 201, 204, 404, 409 and 422 in api_contract.md.
  • Poznámka obsahuje id, title, body a archived. ID prideľuje server a klient ho nesmie vytvoriť alebo zmeniť.A note has id, title, body and archived. The server assigns ID; clients may not create or modify it.

Úloha 2 — Modely s presným významomTask 2 — Models with precise semantics

Tvar vstupu musí byť jednoznačný aj pri prázdnom texte a neznámom poli.Input must be unambiguous for blank text and unknown fields.

  • Title po odstránení okrajových medzier má 1–120 znakov; body má najviac 5000 znakov a môže byť null. Archived je boolean, pri vytvorení false.Trimmed title must contain 1–120 characters; body is at most 5000 characters and may be null. Archived is boolean and defaults to false on creation.
  • Neznáme vstupné polia odmietnite. Výstup obsahuje iba verejné polia a je čitateľný z uloženého objektu.Reject unknown input fields. Responses contain only public fields and can be produced from stored objects.
  • Overte title tvorené medzerami, prekročenú dĺžku, chýbajúce title a klientom poslané id. Neplatný vstup nesmie vytvoriť záznam.Test whitespace-only and overlong titles, missing title and client-provided ID. Invalid input must not create a record.

Úloha 3 — Vytvorenie a konflikt názvuTask 3 — Creation and title conflict

Názov poznámky je jedinečný po odstránení okrajových medzier; veľkosť písmen sa rozlišuje.Titles are unique after trimming and case-sensitive.

  • POST /items uloží poznámku do SQLite, vráti 201 a objekt s kladným serverovým ID.POST /items persists a note in SQLite and returns 201 with a positive server-assigned ID.
  • Druhé vytvorenie rovnakého normalizovaného názvu vráti 409. Pôvodná poznámka aj stav session musia zostať použiteľné.Creating the same normalized title again returns 409 while preserving the original note and a usable session.
  • Odlišný názov vytvorte aj po konflikte. Neočakávanú chybu databázy nevydávajte automaticky za konflikt názvu.Create a different title after a conflict. Do not label every unexpected database error as a title conflict.

Úloha 4 — Detail a stabilný zoznamTask 4 — Detail and stable listing

Klient musí vedieť načítať uložený objekt aj obmedzený prehľad.Clients must be able to read a persisted object and a bounded overview.

  • GET /items/{id} vráti uložený objekt alebo 404. Po vytvorení musí fungovať v samostatnom requeste.GET /items/{id} returns the stored object or 404, including in a separate request after creation.
  • GET /items podporuje limit 1–100 s defaultom 20 a nezáporný offset s defaultom 0. Poradie je podľa id vzostupne.GET /items supports limit 1–100, default 20, and nonnegative offset, default 0, ordered by ascending ID.
  • Prázdny zoznam je 200 s poľom, nie 404. Limit a offset uplatnite pri načítaní dát, nie až po načítaní celej databázy.An empty list is 200 with an array, not 404. Apply limit and offset when fetching rather than after loading the entire database.

Úloha 5 — Čiastočná úprava a nullTask 5 — Partial updates and null

Tu má null zámerne iný význam než pri rezervačnom príklade: telo poznámky sa dá vymazať.Here null deliberately differs from the reservation example: it can clear a note's body.

  • PATCH /items/{id} mení iba poslané polia. Neposlané body zostane pôvodné; explicitné body: null ho vymaže.PATCH /items/{id} changes only provided fields. Omitted body stays unchanged; explicit body: null clears it.
  • Title: null, archived: null, neznáme polia aj prázdny patch odmietnite s 422. Validácia sa nesmie spoliehať iba na aktuálnu hodnotu defaultu.Reject title: null, archived: null, unknown fields and empty patches with 422. Do not rely only on a field's default value.
  • Konflikt názvu je 409 a neexistujúca poznámka 404. Pri chybe sa nesmie čiastočne zmeniť body ani archived.A title conflict returns 409 and a missing note 404. On failure, body and archived must remain unchanged.

Úloha 6 — Archív a vyhľadávanieTask 6 — Archiving and search

Archivovaná poznámka zostáva uložená, ale v základnom zozname ju nechceme vidieť.Archived notes remain persisted but are hidden from the default list.

  • Pridajte include_archived s defaultom false. Pri true vráťte aktívne aj archivované poznámky; detail funguje v oboch stavoch.Add include_archived, default false. True returns both active and archived notes; detail works in either state.
  • Voliteľné q hľadá doslovný podreťazec v názve a rozlišuje veľkosť písmen. Znaky % a _ sú normálny text, nie zástupné vzory.Optional q performs a case-sensitive literal title substring search. Treat % and _ as ordinary text, not wildcards.
  • Najprv aplikujte filtre a až potom offset/limit. Ukážte kombináciu archívu, vyhľadávania a druhej stránky výsledkov.Apply filters before offset/limit. Demonstrate archive, search and a second results page together.

Úloha 7 — Trvalé zmazanieTask 7 — Permanent deletion

Archivácia a fyzické zmazanie sú rôzne operácie.Archiving and physical deletion are distinct operations.

  • DELETE existujúcej poznámky vráti 204 so skutočne prázdnym telom. Nasledujúci detail je 404 a objekt zmizne zo všetkých zoznamov.Deleting an existing note returns 204 with an empty body. Subsequent detail is 404 and all lists omit it.
  • DELETE neexistujúcej poznámky vracia 404. Funguje aj zmazanie archivovanej poznámky.Deleting a nonexistent note returns 404; archived notes can also be deleted.
  • Po zmazaní sa dá vytvoriť nový objekt s pôvodným názvom. Výsledok potvrďte ďalším requestom, nie iba odpoveďou DELETE.After deletion the old title can be reused. Verify state with another request, not just the DELETE response.

Úloha 8 — Reštart a konfigurácia databázyTask 8 — Restart and database configuration

Dáta nesmú existovať iba v pamäti servera alebo iba počas jednej session.Data must not exist only in server memory or a single session.

  • Vytvorte poznámku, zastavte a znovu spustite aplikáciu s rovnakou databázou a overte jej načítanie.Create a note, restart the app with the same database and verify it can be read.
  • Spustite aplikáciu nad druhou prázdnou databázou cez konfiguráciu bez úpravy zdrojov; pôvodné dáta zostanú zachované.Use configuration to run against a second empty database without source edits, preserving original data.
  • Vysvetlite rozdiel engine, session a transakcia. Create_all neoznačujte za všeobecné migrovanie existujúcej schémy.Explain engine, session and transaction. Do not describe create_all as general migration of an existing schema.

Úloha 9 — Testy bez pracovnej databázyTask 9 — Tests without the working database

Každý test má vlastný počiatočný stav a musí overiť konkrétne pravidlo.Each test needs an isolated starting state and a specific assertion.

  • Použite izolovanú dočasnú SQLite a overte, že testy nečítajú ani nemažú notes.db z bežného spustenia.Use an isolated temporary SQLite database and verify tests neither read nor delete the normal notes.db.
  • Napíšte aspoň osem testov: create→read, validácia title, konflikt a pokračovanie po ňom, null pri PATCH, archív, filter/stránkovanie, DELETE a 404.Write at least eight tests: create→read, title validation, conflict recovery, PATCH null, archive, filtering/pagination, DELETE and 404.
  • Regresný test doslovného vyhľadávania musí obsahovať názvy s % alebo _. Po skončení upracte testovacie dependencies a sessions.Include a literal-search regression using % or _ in titles. Clean up overridden dependencies and sessions afterward.

Úloha 10 — Odovzdanie použiteľného APITask 10 — Deliver a usable API

Pripravte projekt tak, aby ho kolega spustil od čistého prostredia a vedel odlíšiť jeho hranice.Prepare the project for a colleague to run from a clean environment and understand its limits.

  • V README uveďte inštaláciu, konfiguráciu, spustenie, testy a ukážkové requesty pre vytvorenie, archív, vyhľadanie a vymazanie body.Document installation, configuration, running, tests and sample requests for creation, archiving, search and clearing body.
  • Zosúlaďte api_contract.md a OpenAPI s reálnymi statusmi a významom null. Žiadne zadanie nesmie zostať nahradené odpoveďou 501.Align api_contract.md and OpenAPI with actual statuses and null semantics. No required endpoint may remain a 501 stub.
  • Popíšte, čo pred verejným nasadením chýba: identita, oprávnenia, zálohy, migrácie a bezpečné logovanie. Databázu ani tajomstvá necommitujte.Describe what public deployment still needs: identity, authorization, backups, migrations and safe logging. Do not commit a database or secrets.

OdovzdanieDeliverables

  • Funkčný projekt, testy, README a api_contract.md. Verejne vystavená služba ani frontend nie sú súčasťou cvičenia.Deliver the working project, tests, README and api_contract.md. A publicly hosted service and frontend are not required.
