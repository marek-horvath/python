  • používať bezpečné parametrizované SQL dotazy cez sqlite3;
  • pracovať s JOIN, transakciami a chybami databázy;

  • use safe parameterized SQL queries through sqlite3;
  • work with JOIN, transactions and database errors;
  • compare explicit SQL with a basic SQLAlchemy 2.x model.

ÚlohyTasks

Úloha 1 — Návrh schémy knižniceTask 1 — Library Schema Design

Navrhnite SQLite schému pre malú knižnicu. Databáza má evidovať knihy, členov a výpožičky.

Minimálne tabuľky:

  • books: názov, autor, rok, ISBN, počet kusov;
  • members: meno, email, dátum registrácie;
  • loans: kniha, člen, dátum požičania, termín vrátenia, dátum vrátenia.

Schéma má obsahovať:

  • primary keys;
  • NOT NULL pre povinné hodnoty;
  • UNIQUE pre ISBN a email;
  • foreign keys medzi výpožičkami, knihami a členmi;
  • aspoň jeden CHECK constraint, napríklad počet kusov nesmie byť záporný.

Design a SQLite schema for a small library. The database should track books, members and loans.

Minimum tables:

  • books: title, author, year, ISBN, copy count;
  • members: name, email, registration date;
  • loans: book, member, borrowed date, due date, returned date.

The schema should include:

  • primary keys;
  • NOT NULL for required values;
  • UNIQUE for ISBN and email;
  • foreign keys between loans, books and members;
  • at least one CHECK constraint, for example copy count must not be negative.
CREATE TABLE books (
    id INTEGER PRIMARY KEY,
    title TEXT NOT NULL,
    author TEXT NOT NULL,
    year INTEGER,
    isbn TEXT UNIQUE NOT NULL,
    copies INTEGER NOT NULL CHECK (copies >= 0)
);

Create a script library_db.py that creates library.db from schema.sql.

Requirements:

  • use sqlite3.connect();
  • enable foreign keys with PRAGMA foreign_keys = ON;
  • load the schema from a file, not from a large string in code;
  • the script should be safe to run repeatedly;
  • after creation, print table names.
Database: library.db
Tables:
- books
- members
- loans

Pomôcka: Viac SQL príkazov zo súboru môžete spustiť cez connection.executescript().

Hint: You can execute multiple SQL statements from a file with connection.executescript().

Úloha 7 — Transakcia pri požičaní knihyTask 7 — Transaction When Borrowing a Book

Implementujte funkciu borrow_book(connection, member_email: str, isbn: str, borrowed_at: str, due_at: str).

Operácia má v jednej transakcii:

  • nájsť člena;
  • nájsť knihu;
  • overiť, že existuje voľný kus;
  • vytvoriť záznam v loans;
  • znížiť počet dostupných kusov.

Ak ktorýkoľvek krok zlyhá, databáza nesmie zostať v polovičnom stave.

Implement borrow_book(connection, member_email: str, isbn: str, borrowed_at: str, due_at: str).

The operation should do the following in one transaction:

  • find the member;
  • find the book;
  • verify that an available copy exists;
  • create a record in loans;
  • decrease the number of available copies.

If any step fails, the database must not remain in a partial state.

borrow_book("anna@example.com", "9780132350884") -> OK
borrow_book("missing@example.com", "9780132350884") -> unknown member
borrow_book("anna@example.com", "missing-isbn") -> unknown book
borrow_book("peter@example.com", "9781449373320") -> no available copies

Pomôcka: Použite commit() až po úspechu všetkých krokov a rollback() pri chybe.

Hint: Use commit() only after all steps succeed and rollback() on error.

Úloha 8 — Constraints a chybové stavyTask 8 — Constraints and Error States

Vytvorte krátky testovací skript, ktorý zámerne skúsi porušiť pravidlá databázy.

Overte tieto situácie:

  • duplicitné ISBN;
  • duplicitný email;
  • záporný počet kusov;
  • výpožička pre neexistujúcu knihu;

Create a short test script that intentionally tries to violate database rules.

Check these situations:

  • duplicate ISBN;
  • duplicate email;
  • negative copy count;
  • a loan for a non-existing book;
  • a loan for a non-existing member.

The program should catch these errors and print a readable result.

duplicate isbn: rejected
duplicate email: rejected
negative copies: rejected
unknown book loan: rejected
unknown member loan: rejected

Neriešte chyby tak, že ich potichu ignorujete. Chyba má byť viditeľná a pochopiteľná.

Do not handle errors by silently ignoring them. An error should be visible and understandable.

Úloha 9 — SQLAlchemy 2.x modelyTask 9 — SQLAlchemy 2.x Models

V súbore library_orm.py vytvorte ORM modely pre rovnakú doménu.

Modely majú používať:

  • DeclarativeBase;
  • Mapped;
  • mapped_column;
  • primary keys;
  • unique constraints;
  • foreign keys;
  • relationships tam, kde zlepšia čitateľnosť práce s dátami.

Create ORM models for the same domain in library_orm.py.

The models should use:

  • DeclarativeBase;
  • Mapped;
  • mapped_column;
  • primary keys;
  • unique constraints;
  • foreign keys;
  • relationships where they improve readability when working with data.
class Book(Base):
    __tablename__ = "books"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str]
    author: Mapped[str]
    isbn: Mapped[str] = mapped_column(unique=True)
    copies: Mapped[int]

Nevytvárajte zbytočne rozsiahlu ORM vrstvu. Cieľom je pochopiť mapovanie medzi tabuľkou a Python objektom.

Do not create an unnecessarily large ORM layer. The goal is to understand the mapping between a table and a Python object.
