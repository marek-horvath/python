PrípravaSetup

Vytvoríte dátovú vrstvu pre univerzitnú požičovňu techniky. Evidovať budete vybavenie, zákazníkov a výpožičky.

Python 3.x
Štandardná knižnica: sqlite3
Dependency pre ORM časť: sqlalchemy
Databáza: equipment_rental.db
Súbory: schema.sql, equipment_db.py, orm_tasks.py

You will build a data layer for a university equipment rental service. It will track equipment, customers and rentals.

Python 3.x
Standard library: sqlite3
Dependency for the ORM part: sqlalchemy
Database: equipment_rental.db
Files: schema.sql, equipment_db.py, orm_tasks.py
python -m pip install sqlalchemy

Stiahnuť starter ZIPDownload starter ZIP

Starter obsahuje vstupné dáta, signatúry funkcií a prázdnu schému. SQL ani ORM modely nie sú vyriešené.

The starter contains input data, function signatures and an empty schema. The SQL and ORM models are not solved.

CieleGoals

  • previesť pravidlá reálnej domény do relačnej schémy;
  • písať parametrizované dotazy a čitateľné databázové funkcie;
  • spájať a agregovať dáta z viacerých tabuliek;
  • chrániť viac-krokové operácie transakciou;
  • porovnať priame SQL s ORM prístupom v SQLAlchemy 2.x.
  • translate real domain rules into a relational schema;
  • write parameterized queries and readable database functions;
  • join and aggregate data from multiple tables;
  • protect multi-step operations with a transaction;
  • compare direct SQL with the SQLAlchemy 2.x ORM approach.

ÚlohyTasks

Úloha 1 — Dátový model požičovneTask 1 — Rental Data Model

Navrhnite v schema.sql tabuľky equipment, customers a rentals.

Model musí zachytiť tieto pravidlá:

  • každý typ vybavenia má unikátny asset_code, názov, kategóriu, dennú cenu a počet dostupných kusov;
  • zákazník má unikátny email a môže byť zablokovaný;
  • výpožička patrí jednému zákazníkovi a jednému typu vybavenia;
  • dátum vrátenia je pri aktívnej výpožičke prázdny;
  • cena ani počty kusov nesmú byť záporné.

Použite primary keys, foreign keys, NOT NULL, UNIQUE a vhodné CHECK constraints. Konkrétne SQL navrhnite sami.

Design the equipment, customers and rentals tables in schema.sql.

The model must capture these rules:

  • each equipment type has a unique asset_code, name, category, daily price and available count;
  • a customer has a unique email and may be blocked;
  • a rental belongs to one customer and one equipment type;
  • the return date is empty for an active rental;
  • prices and item counts cannot be negative.

Use primary keys, foreign keys, NOT NULL, UNIQUE and suitable CHECK constraints. Design the concrete SQL yourself.

Úloha 2 — Inicializácia a kontrola schémyTask 2 — Schema Initialisation and Inspection

Doplňte create_schema(connection). Schému načítajte zo súboru, zapnite foreign keys a umožnite bezpečné opakované spustenie.

Potom vytvorte describe_schema(connection), ktorá z databázových metadát vypíše tabuľky a ich stĺpce. Zoznam názvov nezapisujte natvrdo do Pythonu.

Complete create_schema(connection). Load the schema from a file, enable foreign keys and allow safe repeated execution.

Then create describe_schema(connection), which prints tables and their columns from database metadata. Do not hard-code the names in Python.

equipment: id, asset_code, name, category, daily_rate, available_count
customers: id, name, email, blocked
rentals: id, customer_id, equipment_id, rented_at, due_at, returned_at, daily_rate

Úloha 3 — Opakovateľný seedTask 3 — Repeatable Seed

Použite dáta zo seed_data.py a doplňte seed_database(connection).

  • všetky hodnoty odovzdávajte cez SQL parametre;
  • druhé spustenie nesmie vytvoriť duplicity;
  • neplatný záznam nesmie skryto prerušiť spracovanie celej dávky;
  • na konci vypíšte počty vložených a preskočených riadkov.

Use the data from seed_data.py and complete seed_database(connection).

  • pass every value through SQL parameters;
  • a second run must not create duplicates;
  • one invalid record must not silently interrupt the entire batch;
  • print inserted and skipped row counts at the end.
Equipment inserted: 5, skipped: 0
Customers inserted: 4, skipped: 0

Second run:
Equipment inserted: 0, skipped: 5
Customers inserted: 0, skipped: 4

Úloha 4 — Vyhľadávanie podľa viacerých filtrovTask 4 — Search with Multiple Filters

Doplňte funkciu search_equipment(). Musí podporovať nepovinnú kategóriu, maximálnu dennú cenu a prepínač iba dostupných položiek.

  • ľubovoľná kombinácia filtrov musí fungovať;
  • dotaz musí zostať parametrizovaný;
  • výsledky zoraďte podľa kategórie, ceny a názvu;
  • prázdny výsledok vráťte ako prázdny zoznam.

Complete search_equipment(). It must support an optional category, maximum daily rate and an available-only switch.

  • any combination of filters must work;
  • the query must remain parameterized;
  • sort results by category, price and name;
  • return an empty list when nothing matches.
search_equipment(
    connection,
    category="audio",
    max_daily_rate=15.0,
    available_only=True,
)

Úloha 5 — Report aktívnych výpožičiekTask 5 — Active Rental Report

Vytvorte jeden JOIN dotaz, ktorý spojí všetky tri tabuľky a vráti aktívne výpožičky.

Každý riadok má obsahovať meno a email zákazníka, kód a názov vybavenia, dátum požičania, termín vrátenia a dennú cenu zachytenú pri požičaní. Omeškané výpožičky zobrazte ako prvé.

Create one JOIN query that combines all three tables and returns active rentals.

Each row must contain the customer name and email, equipment code and name, rental date, due date and daily rate captured at checkout. Show overdue rentals first.

OVERDUE | Peter Novák | CAM-02 | Mirrorless camera | due 2026-10-20
ACTIVE  | Anna Horváthová | MIC-01 | USB microphone | due 2026-10-29

Úloha 6 — Súhrn inventáraTask 6 — Inventory Summary

Pripravte agregovaný report po kategóriách. Pre každú kategóriu vypíšte počet typov vybavenia, počet dostupných kusov, priemernú dennú cenu a počet aktívnych výpožičiek.

Kategória bez aktívnej výpožičky musí zostať vo výsledku. Rozhodnite, aký JOIN na to potrebujete, a vysvetlite rozhodnutie jednou vetou v README.

Prepare an aggregate report by category. For each category, print the number of equipment types, available units, average daily rate and active rentals.

A category with no active rental must remain in the result. Decide which JOIN is needed and explain the decision in one sentence in the README.

audio  | types 2 | available 5 | avg 9.50  | active 1
camera | types 2 | available 1 | avg 22.50 | active 1
light  | types 1 | available 4 | avg 8.00  | active 0

Úloha 7 — Transakčné požičanieTask 7 — Transactional Checkout

Doplňte checkout_equipment(). V jednej transakcii musí:

  • nájsť zákazníka a odmietnuť zablokovaného;
  • nájsť vybavenie a overiť dostupný kus;
  • overiť, že termín vrátenia nie je pred dátumom požičania;
  • uložiť výpožičku s aktuálnou dennou cenou;
  • znížiť dostupný počet práve o jeden.

Pri akejkoľvek chybe musí zostať počet kusov aj tabuľka výpožičiek nezmenená.

Complete checkout_equipment(). In one transaction it must:

  • find the customer and reject a blocked one;
  • find the equipment and verify availability;
  • verify that the due date is not before the rental date;
  • store the rental with the current daily rate;
  • decrease the available count by exactly one.

On any error, both the item count and rentals table must remain unchanged.

Úloha 8 — Bezpečné vrátenie a poplatokTask 8 — Safe Return and Fee

Doplňte return_equipment(connection, rental_id, returned_at).

  • vrátenie nastaví dátum a zvýši dostupný počet v jednej transakcii;
  • tú istú výpožičku nemožno vrátiť dvakrát;
  • pri omeškaní vypočítajte poplatok za každý začatý deň po termíne;
  • neexistujúce ID musí vyvolať zrozumiteľnú chybu bez zmeny databázy.

Complete return_equipment(connection, rental_id, returned_at).

  • the return sets the date and increases availability in one transaction;
  • the same rental cannot be returned twice;
  • for a late return, calculate a fee for each started day after the deadline;
  • a missing ID must raise a readable error without changing the database.
return_equipment(4, "2026-10-23") -> returned, late fee 45.00 EUR
return_equipment(4, "2026-10-23") -> already returned
return_equipment(999, "2026-10-23") -> rental not found

Úloha 9 — Rovnaký model cez SQLAlchemyTask 9 — The Same Model with SQLAlchemy

V orm_tasks.py vytvorte SQLAlchemy 2.x modely pre tri tabuľky. Použite DeclarativeBase, typované Mapped, mapped_column, foreign keys a obojsmerné relationships.

Implementujte jednu zapisovaciu operáciu a jeden dotaz:

  • pridanie nového typu vybavenia cez Session;
  • načítanie zákazníkov, ktorí majú aspoň jednu aktívnu výpožičku, bez duplicít.

Starter zámerne neobsahuje hotové modely. Názvy atribútov a relationships navrhnite sami.

Create SQLAlchemy 2.x models for the three tables in orm_tasks.py. Use DeclarativeBase, typed Mapped, mapped_column, foreign keys and bidirectional relationships.

Implement one write operation and one query:

  • add a new equipment type through a Session;
  • load customers with at least one active rental, without duplicates.

The starter intentionally contains no completed models. Design attribute and relationship names yourself.

Úloha 10 — Konzolová dátová vrstvaTask 10 — Console Data Layer

Prepojte predchádzajúce funkcie do malého CLI. Rozhranie nemusí vyzerať presne ako ukážka, ale musí podporovať rovnaké operácie.

Connect the previous functions into a small CLI. The interface does not need to match the example exactly, but it must support the same operations.

python equipment_db.py init
python equipment_db.py search --category audio --available
python equipment_db.py checkout anna@example.com MIC-01 --due 2026-10-30
python equipment_db.py return 3 --date 2026-10-31
python equipment_db.py active
python equipment_db.py summary

Pred odovzdaním overte:

  • čistú inicializáciu aj opakované spustenie;
  • úspešné a neúspešné požičanie;
  • dvojité vrátenie tej istej výpožičky;
  • prázdne výsledky filtrov a reportov;
  • že žiadny SQL dotaz neskladá používateľské hodnoty cez f-string.

Before submission, verify:

  • clean initialisation and repeated execution;
  • successful and rejected checkout;
  • a double return of the same rental;
  • empty filter and report results;
  • that no SQL query inserts user values through an f-string.
