Skriptovanie a automatizáciaScripting and Automation · približne 90 minútapproximately 90 minutes

PrípravaSetup

Stiahnite si starter ZIP a rozbaľte ho do samostatného pracovného priečinka. Pracujte iba s priloženými testovacími súbormi, nie so svojimi osobnými dátami.Download the starter ZIP and extract it into a separate working directory. Work only with the supplied test files, not with personal data.

Stiahnuť starter ZIPDownload starter ZIP

exercise-02/
├── organizer.py
└── subory/
    ├── FOTO.JPG
    ├── report.pdf
    ├── poznamky.txt
    ├── README
    └── podklady/

Pred úlohami, ktoré menia súbory, si vytvorte čistú kópiu priečinka subory/. Jednotlivé úlohy opisujú požadované správanie; spôsob implementácie navrhnite sami podľa prednášky a dokumentácie.Before tasks that modify files, create a clean copy of subory/. Each task describes required behaviour; design the implementation yourself using the lecture and documentation.

Výsledok cvičeniaExercise Outcome

Výsledkom bude príkazový nástroj, ktorý triedi bezprostredné súbory podľa prípony. Predvolený režim iba zobrazí plán. Zmenu na disku vykoná až po explicitnom potvrdení, neprechádza podadresáre a neprepisuje existujúce súbory.The result will be a command-line tool that sorts immediate files by suffix. Its default mode only shows a plan. It changes the disk only after explicit confirmation, does not traverse subdirectories and does not overwrite existing files.

Úloha 1 — Inventúra priečinkaTask 1 — Directory Inventory

8 min

Doplňte program tak, aby pre každú bezprostrednú položku v subory/ vypísal názov, typ a príponu.

Výpis musí rozlíšiť súbor od priečinka, súbor bez prípony a príponu zapísanú veľkými písmenami. Poradie riadkov sa nemusí zhodovať s ukážkou.

Complete the program so it prints the name, type and suffix of every immediate entry in subory/.

The output must distinguish a file from a directory, a suffixless file and an uppercase suffix. Line order does not have to match the example.

FOTO.JPG       súbor      .JPG
report.pdf     súbor      .pdf
poznamky.txt   súbor      .txt
README         súbor      bez prípony
podklady       priečinok  -

Úloha 2 — Pravidlá kategorizácieTask 2 — Categorisation Rules

8 min

Pre každý súbor určte názov cieľovej kategórie. Kategória zodpovedá prípone bez bodky a bez rozdielu medzi veľkými a malými písmenami. Súbor bez prípony patrí do bez_pripony.

Overte pravidlá aspoň na všetkých štyroch súboroch zo startera.

Determine the destination category name for each file. A category corresponds to the suffix without its dot and without a distinction between uppercase and lowercase. A suffixless file belongs in bez_pripony.

Verify the rules on at least all four starter files.

FOTO.JPG -> jpg
report.pdf -> pdf
poznamky.txt -> txt
README -> bez_pripony

Úloha 3 — Plán cieľových ciestTask 3 — Destination Plan

10 min

Z predchádzajúcich pravidiel vytvorte plán organizácie. Každý riadok musí obsahovať pôvodný názov a relatívnu cieľovú cestu.

Spustenie tejto verzie nesmie vytvoriť priečinok, premenovať súbor ani zmeniť obsah subory/.

Build an organisation plan from the previous rules. Each line must contain the original name and relative destination path.

Running this version must not create a directory, rename a file or change the contents of subory/.

PLAN: FOTO.JPG -> jpg/FOTO.JPG
PLAN: report.pdf -> pdf/report.pdf
PLAN: poznamky.txt -> txt/poznamky.txt
PLAN: README -> bez_pripony/README

Úloha 4 — Hranica spracovaniaTask 4 — Processing Boundary

8 min

Do podklady/ pridajte súbor archiv.zip. Program musí naďalej plánovať iba štyri pôvodné súbory.

Priečinok podklady/ ani jeho obsah nesmie byť cieľom presunu. Túto hranicu zachovajte aj vo všetkých ďalších úlohách.

Add archiv.zip inside podklady/. The program must still plan only the four original files.

Neither podklady/ nor its contents may become a move target. Preserve this boundary in all following tasks.

Počet naplánovaných súborov: 4
podklady/archiv.zip sa vo výstupe nenachádza

Úloha 5 — Neplatný vstupTask 5 — Invalid Input

8 min

Program musí odmietnuť cestu, ktorá neexistuje, aj cestu smerujúcu na obyčajný súbor. V oboch prípadoch vypíšte zrozumiteľnú chybu a nevykonajte žiadnu ďalšiu operáciu.

The program must reject both a path that does not exist and a path pointing to a regular file. In both cases, print a clear error and perform no further operation.

python organizer.py neexistuje
python organizer.py subory/report.pdf
CHYBA: vstup nie je existujúci priečinok: neexistuje

Úloha 6 — Kolízia cieľaTask 6 — Destination Collision

10 min

Vytvorte testovací stav, v ktorom už existuje subory/jpg/FOTO.JPG, pričom pôvodný subory/FOTO.JPG zostane na mieste.

Program nesmie existujúci cieľ prepísať ani zmeniť. Konfliktný súbor označí ako preskočený a pokračuje ďalšími položkami.

Create a test state where subory/jpg/FOTO.JPG already exists while the original subory/FOTO.JPG remains in place.

The program must not overwrite or modify the existing target. It marks the conflicting file as skipped and continues with the remaining entries.

PRESKOCENE: FOTO.JPG (cieľ už existuje)
PLAN: report.pdf -> pdf/report.pdf
PLAN: poznamky.txt -> txt/poznamky.txt
PLAN: README -> bez_pripony/README

Úloha 7 — Bezpečný predvolený režimTask 7 — Safe Default Mode

8 min

Obnovte čisté vstupné dáta. Bežné spustenie programu musí iba vypísať plán. Porovnajte obsah priečinka pred spustením a po ňom.

Ak sa bez výslovného potvrdenia zmení čo i len jeden súbor alebo vznikne nový priečinok, úloha nie je splnená.

Restore clean input data. A normal program run must only print a plan. Compare the directory contents before and after running it.

If even one file changes or a new directory appears without explicit confirmation, the task is not complete.

python organizer.py subory

Úloha 8 — Vykonanie plánuTask 8 — Execute the Plan

10 min

Pridajte režim, ktorý po explicitnom potvrdení vykoná rovnaký plán. Po úspešnom spustení musí vzniknúť nasledujúca štruktúra a podklady/ musí zostať zachovaný.

Každú úspešnú zmenu oznámte vo výstupe. Pravidlo o neprepisovaní cieľa zostáva platné.

Add a mode that executes the same plan after explicit confirmation. After a successful run, the following structure must exist and podklady/ must remain preserved.

Report every successful change in the output. The no-overwrite rule remains in effect.

subory/
├── bez_pripony/README
├── jpg/FOTO.JPG
├── pdf/report.pdf
├── txt/poznamky.txt
└── podklady/

Úloha 9 — Príkazové rozhranieTask 9 — Command-Line Interface

10 min

Dokončite rozhranie programu tak, aby prijímalo povinnú cestu k priečinku a voliteľný prepínač --vykonat.

Bez cesty má program zobraziť stručnú nápovedu. Cesta môže byť relatívna aj absolútna. Bez prepínača zostáva aktívny bezpečný plánovací režim.

Complete the program interface so it accepts a required directory path and an optional --vykonat flag.

Without a path, the program should display concise help. The path may be relative or absolute. Without the flag, safe planning mode remains active.

python organizer.py subory
python organizer.py subory --vykonat
python organizer.py

Úloha 10 — Súhrn a opakované spustenieTask 10 — Summary and Repeated Run

10 min

Na konci každého spustenia vypíšte súhrn: počet spracovaných, naplánovaných alebo presunutých a preskočených súborov spolu s počtami podľa kategórie.

Overte aj opakované spustenie po úspešnom presune. Program nesmie poškodiť už usporiadanú štruktúru ani začať spracúvať vytvorené kategórie.

At the end of every run, print a summary: processed, planned or moved, and skipped file counts together with counts by category.

Also test a repeated run after a successful move. The program must not damage the organised structure or start processing the category directories it created.

SÚHRN
Spracované súbory: 4
Naplánované: 4
Preskočené: 0

Podľa kategórie:
bez_pripony: 1
jpg: 1
pdf: 1
txt: 1

Akceptačný checklistAcceptance Checklist

  • predvolený režim nemení súborový systém;
  • FOTO.JPG skončí v jpg/ a README v bez_pripony/;
  • podadresáre a ich obsah sa nespracúvajú;
  • existujúci cieľ sa nikdy neprepíše;
  • neplatný vstup skončí čitateľnou chybou;
  • CLI funguje s relatívnou aj absolútnou cestou;
  • výstup obsahuje zrozumiteľný súhrn.
  • default mode does not change the filesystem;
  • FOTO.JPG ends up in jpg/ and README in bez_pripony/;
  • subdirectories and their contents are not processed;
  • an existing target is never overwritten;
  • invalid input ends with a clear error;
  • the CLI works with relative and absolute paths;
  • the output contains a clear summary.
