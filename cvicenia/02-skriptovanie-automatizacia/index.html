PrípravaSetup

Python 3.x
Externé knižnice: nie
Odporúčané: samostatný pracovný priečinok
Odovzdávané súbory: .py skripty podľa úloh
Python 3.x
External libraries: no
Recommended: a separate working directory
Submitted files: .py scripts for the tasks

CieleGoals

  • písať použiteľné skripty bez hardcoded absolútnych ciest;
  • pracovať so súbormi a adresármi cez pathlib;
  • spracovať JSON, CSV, text a logy;
  • navrhovať CLI cez argparse;
  • ošetriť chyby pri práci s filesystemom a externými príkazmi.
  • write usable scripts without hardcoded absolute paths;
  • work with files and directories through pathlib;
  • process JSON, CSV, text and logs;
  • design a CLI with argparse;
  • handle errors when working with the filesystem and external commands.

ÚlohyTasks

Úloha 1 — Filesystem reportTask 1 — Filesystem Report

Napíšte skript scan.py, ktorý rekurzívne analyzuje zadaný adresár.

Write a script scan.py that recursively analyzes a given directory.

python scan.py ./project

Výstup musí obsahovať:

  • počet súborov;
  • počet adresárov;
  • počet súborov podľa prípony;
  • päť najväčších súborov;
  • celkovú veľkosť súborov;
  • počet súborov bez prípony.

Použite pathlib, sorting a vhodnú kolekciu na počítanie prípon. Program má rozumne reagovať na neexistujúci adresár.

The output must include:

  • number of files;
  • number of directories;
  • number of files by extension;
  • the five largest files;
  • total file size;
  • number of files without an extension.

Use pathlib, sorting and a suitable collection for counting extensions. The program should handle a missing directory reasonably.

$ python scan.py ./project

Files: 84
Directories: 12
Total size: 2.4 MB
Without extension: 3

By extension:
.py      28
.md       4
.json     3

Largest files:
data/sample.csv       842 KB
assets/image.png      418 KB
dist/bundle.js        211 KB

Pomôcka: Veľkosť súboru získate cez Path.stat(). Pri chybách s právami nepoužívajte except: pass.

Hint: Use Path.stat() to get file size. Do not handle permission errors with except: pass.

Úloha 2 — Duplicate finderTask 2 — Duplicate Finder

Napíšte skript, ktorý nájde potenciálne duplicitné súbory v adresári.

Postup riešenia:

  • najprv zoskupte súbory podľa veľkosti;
  • obsah/hash počítajte iba pre skupiny, kde majú aspoň dva súbory rovnakú veľkosť;
  • použite napríklad hashlib;
  • prázdne súbory ignorujte;
  • riešenie rozdeľte do menších funkcií.

Write a script that finds potential duplicate files in a directory.

Suggested procedure:

  • first group files by size;
  • compute content/hash only for groups where at least two files have the same size;
  • use hashlib, for example;
  • ignore empty files;
  • split the solution into smaller functions.
Duplicate group:
photos/photo.jpg
photos/photo-copy.jpg
archive/old/photo.jpg

Duplicate group:
docs/report.pdf
backup/report.pdf

Program nemá porovnávať každý súbor s každým, ak sa tomu dá rozumne vyhnúť.

The program should not compare every file with every other file when that can be reasonably avoided.

Úloha 3 — Batch renameTask 3 — Batch Rename

Vytvorte skript rename.py, ktorý hromadne premenuje súbory v adresári.

Create a script rename.py that renames files in a directory in bulk.

python rename.py ./photos --prefix holiday --start 1
python rename.py ./photos --prefix holiday --start 1 --dry-run

Požiadavky:

  • zachovať pôvodnú príponu súboru;
  • číslovať s nulami, napríklad holiday_001.jpg;
  • neprepísať existujúci súbor;
  • rozumne riešiť kolízie názvov;
  • pri --dry-run nevykonať žiadnu zmenu vo filesysteme;
  • vypísať plánované alebo vykonané premenovania.

Requirements:

  • preserve the original file extension;
  • number files with zero padding, for example holiday_001.jpg;
  • do not overwrite an existing file;
  • handle filename collisions reasonably;
  • when --dry-run is used, do not change the filesystem;
  • print planned or completed renames.
IMG_8472.jpg -> holiday_001.jpg
IMG_9123.jpg -> holiday_002.jpg
IMG_9441.jpg -> holiday_003.jpg

Pomôcka: Cieľovú cestu skladajte cez operátor / nad Path, nie cez ručné spájanie stringov.

Hint: Build the destination path with the / operator on Path, not by manually concatenating strings.

Úloha 4 — Config-driven organizerTask 4 — Config-Driven Organizer

Napíšte organizér súborov riadený JSON konfiguráciou.

Write a file organizer driven by a JSON configuration file.

{
  "images": [".jpg", ".png", ".gif"],
  "documents": [".pdf", ".docx", ".txt"],
  "archives": [".zip", ".7z"]
}
python organize.py ./Downloads --config categories.json
python organize.py ./Downloads --config categories.json --dry-run

Skript má:

  • načítať konfiguračný JSON;
  • vytvoriť mapping extension -> category;
  • kategorizovať iba súbory v zadanom adresári;
  • vytvoriť cieľové adresáre;
  • presunúť súbory do kategórií;
  • neznáme prípony presunúť do other;
  • ošetriť chýbajúci alebo poškodený JSON.

The script should:

  • load the JSON configuration;
  • create an extension -> category mapping;
  • categorize only files in the given directory;
  • create destination directories;
  • move files into categories;
  • move unknown extensions into other;
  • handle a missing or invalid JSON file.
MOVE report.pdf -> documents/report.pdf
MOVE photo.jpg -> images/photo.jpg
MOVE archive.zip -> archives/archive.zip
MOVE data.bin -> other/data.bin

--dry-run nesmie vykonať žiadnu zmenu vo filesysteme.

--dry-run must not make any filesystem changes.

Úloha 5 — CSV cleanerTask 5 — CSV Cleaner

Pripravte si CSV súbor s nekonzistentnými dátami a napíšte skript, ktorý ho vyčistí.

Prepare a CSV file with inconsistent data and write a script that cleans it.

name,email,points
 Anna ,ANNA@example.com,92
Peter,peter@example.com, 67
Lucia,lucia@example.com,
Anna,ANNA@example.com,92
Martin,martin@example.com,abc
Eva, eva@example.com ,88

Skript má:

  • normalizovať whitespace;
  • previesť email na lowercase;
  • odstrániť presné duplicity;
  • validovať, že points je celé číslo;
  • validné riadky uložiť do nového CSV;
  • chybné riadky uložiť do samostatného CSV aj s dôvodom chyby;
  • vypísať stručný report.

The script should:

  • normalize whitespace;
  • convert email to lowercase;
  • remove exact duplicates;
  • validate that points is an integer;
  • write valid rows to a new CSV file;
  • write invalid rows to a separate CSV file with the reason;
  • print a short report.
Processed: 6
Valid: 3
Invalid: 2
Duplicates: 1

Output:
clean_students.csv
invalid_students.csv

Pomôcka: Použite modul csv. Nepokúšajte sa spoľahlivo parsovať CSV cez split(",").

Hint: Use the csv module. Do not try to parse CSV reliably with split(",").

Úloha 6 — Log analysisTask 6 — Log Analysis

Vytvorte skript logstats.py, ktorý analyzuje aplikačný log.

Create a script logstats.py that analyzes an application log.

2026-09-21T10:14:22 INFO api Started request id=REQ-1001
2026-09-21T10:14:23 ERROR storage Cannot open file path=data.csv
2026-09-21T10:15:10 WARNING auth Invalid login user=peter
2026-09-21T10:17:45 ERROR api Timeout id=REQ-1002
2026-09-22T09:03:11 INFO worker Job finished id=JOB-42
python logstats.py application.log
python logstats.py application.log --level ERROR

Program musí:

  • spočítať log levels;
  • nájsť a vypísať ERROR záznamy;
  • zistiť najčastejší module;
  • nájsť časový rozsah logu;
  • podporovať filter --level;
  • použiť regex aspoň na extrakciu identifikátorov typu REQ-1002 alebo JOB-42.

Jednoduché časti riadku riešte cez string operácie. Regex nepoužívajte na všetko.

The program must:

  • count log levels;
  • find and print ERROR records;
  • identify the most frequent module;
  • find the time range of the log;
  • support a --level filter;
  • use regex at least for extracting identifiers such as REQ-1002 or JOB-42.

Handle simple parts of the line with string operations. Do not use regex for everything.

Levels:
INFO: 2
WARNING: 1
ERROR: 2

Most active module: api
Range: 2026-09-21T10:14:22 -> 2026-09-22T09:03:11
IDs: REQ-1001, REQ-1002, JOB-42

Úloha 7 — Text search toolTask 7 — Text Search Tool

Vytvorte jednoduchú mini verziu nástroja grep.

Create a small simplified version of grep.

python search.py ./src "TODO"
python search.py ./src "todo" --ignore-case
python search.py ./src "def .*_handler" --extension .py --regex

Požiadavky:

  • rekurzívne prechádzať súbory v adresári;
  • voliteľne filtrovať príponu cez --extension;
  • podporovať case-insensitive hľadanie;
  • podporovať obyčajný text aj regex režim;
  • pri zhode vypísať cestu, číslo riadku a celý riadok;
  • rozumne zvládnuť encoding errors.

Requirements:

  • walk files in a directory recursively;
  • optionally filter by extension with --extension;
  • support case-insensitive search;
  • support both plain text and regex modes;
  • for each match, print the path, line number and full line;
  • handle encoding errors reasonably.
src/main.py:18: # TODO: validate input
src/api.py:42: # TODO cleanup
src/tasks/runner.py:7: TODO = "replace with config"

Toto má byť reálne použiteľný skript, nie iba demonštračný príklad pre jeden súbor.

This should be a genuinely usable script, not just a demonstration for one file.

Úloha 8 — Backup toolTask 8 — Backup Tool

Vytvorte skript na vytvorenie timestamped zálohy projektu.

Create a script that produces a timestamped project backup.

python backup.py ./project ./backups

Program má:

  • vytvoriť ZIP archív v cieľovom adresári;
  • do názvu zálohy pridať timestamp;
  • ignorovať .venv, __pycache__ a .git;
  • spočítať počet zahrnutých súborov;
  • spočítať celkovú veľkosť zahrnutých súborov;
  • vytvoriť JSON manifest;
  • neprepísať starší backup pri opakovanom spustení.

The program should:

  • create a ZIP archive in the target directory;
  • include a timestamp in the backup name;
  • ignore .venv, __pycache__ and .git;
  • count included files;
  • count total size of included files;
  • create a JSON manifest;
  • avoid overwriting an older backup on repeated runs.
{
  "created": "2026-09-21T13:30:00",
  "source": "project",
  "archive": "project-20260921-133000.zip",
  "files": 84,
  "size": 1048576
}

Pomôcka: Pozrite sa na shutil.make_archive() alebo modul zipfile. Pri ignorovaní adresárov buďte explicitní.

Hint: Look at shutil.make_archive() or the zipfile module. Be explicit when ignoring directories.

Úloha 9 — External command runnerTask 9 — External Command Runner

Vytvorte skript, ktorý spustí sériu externých príkazov definovaných v JSON súbore.

Create a script that runs a series of external commands defined in a JSON file.

{
  "commands": [
    ["python", "--version"],
    ["git", "status"],
    ["git", "log", "-1", "--oneline"]
  ]
}

Pre každý command uložte do JSON reportu:

  • spustený command ako zoznam argumentov;
  • return code;
  • stdout;
  • stderr;
  • status ok, failed alebo not_found.

Použite subprocess.run(...), capture_output=True a text=True. Nepoužívajte shell=True.

For each command, save the following into a JSON report:

  • the executed command as a list of arguments;
  • return code;
  • stdout;
  • stderr;
  • status ok, failed or not_found.

Use subprocess.run(...), capture_output=True and text=True. Do not use shell=True.

[
  {
    "command": ["python", "--version"],
    "returncode": 0,
    "status": "ok"
  },
  {
    "command": ["missing-command"],
    "returncode": null,
    "status": "not_found"
  }
]

Ak command neexistuje, program nemá spadnúť tracebackom.

If a command does not exist, the program should not crash with a traceback.

Úloha 10 — Mini projekt: Project InspectorTask 10 — Mini Project: Project Inspector

Vytvorte CLI nástroj, ktorý analyzuje Python projekt a uloží výsledok do JSON reportu.

Create a CLI tool that analyzes a Python project and stores the result in a JSON report.

python inspect_project.py ./my-project
python inspect_project.py . --output project-report.json

Nástroj má minimálne:

  • skontrolovať existenciu .git;
  • nájsť všetky .py súbory;
  • spočítať počet Python súborov;
  • spočítať počet riadkov Python kódu;
  • nájsť najväčšie súbory v projekte;
  • nájsť riadky obsahujúce TODO alebo FIXME;
  • zistiť prítomnosť README, pyproject.toml, requirements.txt a tests;
  • identifikovať potenciálne veľké binárne súbory;
  • ak ide o Git repository, bezpečne spustiť git status --short;
  • uložiť report do súboru určeného argumentom --output.

The tool should at least:

  • check whether .git exists;
  • find all .py files;
  • count Python files;
  • count lines of Python code;
  • find the largest files in the project;
  • find lines containing TODO or FIXME;
  • detect the presence of README, pyproject.toml, requirements.txt and tests;
  • identify potentially large binary files;
  • if the directory is a Git repository, safely run git status --short;
  • write the report to the file specified by --output.
{
  "path": ".",
  "git": true,
  "python_files": 18,
  "python_lines": 2140,
  "has_readme": true,
  "has_tests": true,
  "todos": [
    "src/main.py:18: # TODO: validate input"
  ],
  "git_status": "clean"
}

Program musí byť rozdelený do viacerých funkcií. Celé riešenie v jednom veľkom main() nebude prehľadné.

The program must be split into multiple functions. A solution contained in one large main() will be hard to read.

Pomôcka: Táto úloha spája pathlib, string processing, JSON, argparse, subprocess, exceptions a collections.

Hint: This task combines pathlib, string processing, JSON, argparse, subprocess, exceptions and collections.
