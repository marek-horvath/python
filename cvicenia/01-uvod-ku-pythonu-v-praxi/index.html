Úloha 1 — Referencie a kópieTask 1 — References and Copies

Bez spustenia programu najprv zapíšte, čo bude po vykonaní kódu obsahovať courses a backup.

    "Python": ["Anna", "Peter"],
    "Databázy": ["Lucia"],
}

backup = courses

backup["Python"].append("Martin")
backup["Web"] = ["Eva"]

print(backup)
print(courses is backup)

Potom program spustite a vysvetlite, prečo sa zmenil aj pôvodný slovník.

  • skutočne nezávislou kópiou vnorených zoznamov.

V poslednom kroku vytvorte kópiu, pri ktorej pridanie nového študenta do backup["Python"] nezmení courses.

Úloha 4 — Pythonic refactoringTask 4 — Pythonic Refactoring

Nasledujúci kód funguje, ale je zbytočne ťažkopádny. Prepíšte ho do prirodzenejšieho Pythonu bez zmeny správania.

The following code works, but it is unnecessarily clumsy. Rewrite it into more natural Python without changing behavior.

names = ["Anna", "Peter", "Lucia", "Martin"]
points = [92, 67, 81, 45]
active = [True, True, False, True]
allowed_names = ["Anna", "Lucia", "Eva"]

rows = []
i = 0
while i < len(names):
    found = False
    for allowed in allowed_names:
        if allowed == names[i]:
            found = True

    if active[i] == True:
        status = "active"
    else:
        status = "inactive"

    row = {
        "index": i,
        "name": names[i],
        "points": points[i],
        "allowed": found,
        "status": status,
    }
    rows.append(row)
    i = i + 1

passed = []
for row in rows:
    if row["points"] >= 51:
        passed.append(row)

passed = sorted(passed, key=lambda row: row["points"])
passed.reverse()

Požiadavky:

  • použite enumerate alebo zip tam, kde to zlepší čitateľnosť;
  • membership netestujte ručným cyklom;
  • nepoužívajte if x == True;
  • zvážte set pre povolené mená;
  • sorting vyriešte priamo cez vhodné argumenty funkcie sorted.

Na konci krátko zapíšte aspoň tri konkrétne zlepšenia, ktoré ste urobili.

Requirements:

  • use enumerate or zip where it improves readability;
  • do not test membership with a manual loop;
  • do not use if x == True;
  • consider set for allowed names;
  • handle sorting directly with appropriate arguments of sorted.

At the end, briefly write down at least three concrete improvements you made.

Úloha 8 — Mutable default argument a debuggingTask 8 — Mutable Default Argument and Debugging

Tento kód pri prvom použití vyzerá správne, ale pri opakovaných volaniach produkuje chybný výsledok.

This code looks correct on first use, but repeated calls produce an incorrect result.

def add_report_event(
    report_name: str,
    event: str,
    history: list[dict[str, str]] = [],
) -> list[dict[str, str]]:
    history.append({"report": report_name, "event": event})
    return history


morning = add_report_event("attendance", "created")
morning = add_report_event("attendance", "exported", morning)

afternoon = add_report_event("grades", "created")

print("Morning:", morning)
print("Afternoon:", afternoon)

Postup:

  • pred spustením predpovedzte, čo bude vo výstupe;
  • spustite kód a reprodukujte chybu;
  • vysvetlite, prečo sa história medzi reportmi zdieľa;
  • opravte implementáciu bez zdieľaného mutabilného defaultu;
  • vytvorte krátky testovací scenár, ktorý dokáže, že dve nezávislé histórie sa už nemiešajú.
attendance: 2 udalosti
grades: 1 udalosť
Histórie sú nezávislé: True

Procedure:

  • predict the output before running the code;
  • run the code and reproduce the bug;
  • explain why history is shared between reports;
  • fix the implementation without a shared mutable default;
  • create a short test scenario proving that two independent histories no longer mix.
