Cvičenie 09Exercise 09

Bezpečné programovanie v PythoneSecure Programming in Python

PrípravaSetup

Toto cvičenie je obranné. Dostanete malý problematický Python projekt a postupne opravíte chyby, ktoré by v reálnej aplikácii predstavovali bezpečnostné alebo prevádzkové riziko.

Starter súbory: exercises/exercise-09/
Hlavné moduly: app.py, database.py, commands.py, files.py, tokens.py
Výstup: opravený projekt + krátky security checklist

Starter súbory sú dostupné aj ako ZIP archív.

This exercise is defensive. You will receive a small problematic Python project and gradually fix issues that would be security or operational risks in a real application.

Starter files: exercises/exercise-09/
Main modules: app.py, database.py, commands.py, files.py, tokens.py
Output: fixed project + short security checklist

Starter files are also available as a ZIP archive.

python -m pip install bandit

CieleGoals

  • nájsť a opraviť bežné bezpečnostné chyby v Python kóde;
  • použiť bezpečnejšie postupy pri SQL, subprocess, secrets, súboroch a serializácii;
  • rozlišovať medzi vstupnou validáciou, chybovým správaním a skutočnou bezpečnosťou;
  • použiť Bandit ako pomocný nástroj, nie ako náhradu vlastného review.
  • find and fix common security issues in Python code;
  • use safer patterns for SQL, subprocess, secrets, files and serialization;
  • distinguish input validation, error behavior and actual security;
  • use Bandit as a supporting tool, not as a replacement for your own review.

ÚlohyTasks

Úloha 1 — Baseline a risk inventoryTask 1 — Baseline and Risk Inventory

Najprv projekt nespúšťajte slepo nad reálnymi dátami. Prejdite si súbory a vytvorte krátky zoznam rizík.

Skontrolujte:

  • app.py: broad exception handling a vypisovanie citlivých údajov;
  • database.py: skladanie SQL cez f-string;
  • commands.py: shell=True s používateľským inputom;
  • files.py: práca s cestami bez kontroly base adresára;
  • tokens.py: hardcoded secret, slabý token, pickle.loads().

Do not run the project blindly on real data first. Review the files and create a short risk inventory.

Check:

  • app.py: broad exception handling and printing sensitive data;
  • database.py: SQL built with f-strings;
  • commands.py: shell=True with user input;
  • files.py: path handling without checking a base directory;
  • tokens.py: hardcoded secret, weak token, pickle.loads().
Risk inventory
- database.py: SQL query is built from user input
- commands.py: shell=True receives user-controlled host
- tokens.py: secret is stored in source code
...

Ku každému problému napíšte jednou vetou, aký typ opravy plánujete. Nepotrebujete vytvárať útočné payloady.

For each issue, write one sentence describing the type of fix you plan. You do not need to create attack payloads.

Úloha 2 — Lokálna databáza a parametrizované SQLTask 2 — Local Database and Parameterized SQL

Pripravte si malú lokálnu SQLite databázu, aby bolo možné funkcie z database.py overiť.

Vytvorte napríklad init_db.py, ktorý založí tabuľku users a vloží 2-3 používateľov.

Prepare a small local SQLite database so functions from database.py can be verified.

Create for example init_db.py, which creates the users table and inserts 2-3 users.

CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE
);

Potom opravte find_user() a create_user() tak, aby používali parametrizované dotazy.

Then fix find_user() and create_user() so they use parameterized queries.

cursor.execute(
    "SELECT id, name, email FROM users WHERE name = ?",
    (name,),
)
find_user("Anna") -> (1, "Anna", "anna@example.com")
create_user("Eva", "eva@example.com") -> OK

Úloha 3 — Validácia vstupu v databázových funkciáchTask 3 — Input Validation in Database Functions

Pridajte jednoduchú validáciu vstupu pred zápisom do databázy.

Požiadavky:

  • meno nesmie byť prázdne po strip();
  • email musí obsahovať @ a nesmie obsahovať whitespace;
  • duplicitný email má skončiť zrozumiteľnou výnimkou alebo chybovým výsledkom;
  • funkcie nemajú potichu ignorovať sqlite3.IntegrityError.

Add simple input validation before writing to the database.

Requirements:

  • name must not be empty after strip();
  • email must contain @ and must not contain whitespace;
  • duplicate email should end with a readable exception or error result;
  • functions must not silently ignore sqlite3.IntegrityError.
create_user("", "empty@example.com") -> rejected
create_user("Eva", "not an email") -> rejected
create_user("Eva 2", "eva@example.com") -> duplicate email

Validácia nie je náhrada parametrizovaného SQL. Potrebujete oboje.

Validation is not a replacement for parameterized SQL. You need both.

Úloha 4 — Bezpečnejší subprocessTask 4 — Safer subprocess

Opravte commands.py. Odstráňte shell=True a posielajte argumenty ako zoznam.

Fix commands.py. Remove shell=True and pass arguments as a list.

import ipaddress
import subprocess

def ping_host(host: str) -> int:
    ipaddress.ip_address(host)
    result = subprocess.run(["ping", host], check=False)
    return result.returncode

Požiadavky:

  • povoľte iba validnú IPv4 alebo IPv6 adresu;
  • pri nevalidnom vstupe vyhoďte ValueError;
  • nepoužívajte shell=True;
  • vráťte returncode.

Poznámka: konkrétne argumenty príkazu ping sa môžu líšiť podľa operačného systému. Pointa úlohy je bezpečné odovzdanie argumentov.

Requirements:

  • allow only a valid IPv4 or IPv6 address;
  • raise ValueError for invalid input;
  • do not use shell=True;
  • return returncode.

Note: exact arguments of the ping command may differ by operating system. The point of this task is safe argument passing.

Úloha 5 — Secrets a konfiguráciaTask 5 — Secrets and Configuration

Odstráňte hardcoded API_KEY zo tokens.py. Hodnotu načítajte z environment variable.

Remove the hardcoded API_KEY from tokens.py. Load the value from an environment variable.

import os

def get_api_key() -> str:
    api_key = os.getenv("API_KEY")
    if not api_key:
        raise RuntimeError("API_KEY is not configured")
    return api_key

Požiadavky:

  • nevypisujte API key v app.py;
  • vytvorte .env.example s názvom premennej, ale bez reálnej hodnoty;
  • skontrolujte, že .env je v .gitignore;
  • ak konfigurácia chýba, chyba má byť zrozumiteľná.

Requirements:

  • do not print the API key in app.py;
  • create .env.example with the variable name, but without a real value;
  • check that .env is in .gitignore;
  • if configuration is missing, the error should be readable.
API_KEY is not configured
Create local .env or set environment variable API_KEY.

Úloha 6 — Reset token cez secretsTask 6 — Reset Token with secrets

Nahraďte token generovaný cez random.randint() bezpečnejším tokenom zo štandardného modulu secrets.

Replace the token generated with random.randint() by a safer token from the standard secrets module.

import secrets

def generate_reset_token() -> str:
    return secrets.token_urlsafe(32)

Overte:

  • token nie je iba šesťmiestne číslo;
  • dva po sebe vygenerované tokeny sa bežne nerovnajú;
  • funkcia nemá závisieť od času ani od ručne nastaveného seedu.

Nevytvárajte vlastný kryptografický algoritmus.

Verify that:

  • the token is not just a six-digit number;
  • two tokens generated in a row are normally different;
  • the function does not depend on time or a manually set seed.

Do not create your own cryptographic algorithm.

Úloha 7 — Path traversal ochranaTask 7 — Path Traversal Protection

Opravte load_file() a save_file() tak, aby používateľ nemohol čítať alebo zapisovať mimo adresára uploads/.

Fix load_file() and save_file() so the user cannot read or write outside the uploads/ directory.

from pathlib import Path

BASE_DIR = Path("uploads").resolve()
target = (BASE_DIR / filename).resolve()

Požiadavky:

  • base adresár vyriešte ako absolútnu cestu;
  • po spojení s používateľským filename opäť zavolajte resolve();
  • overte, že výsledná cesta zostáva v BASE_DIR;
  • pri pokuse o cestu mimo adresára vyhoďte ValueError;
  • pri ukladaní vytvorte uploads/, ak ešte neexistuje.

Requirements:

  • resolve the base directory as an absolute path;
  • after combining it with user-provided filename, call resolve() again;
  • verify that the resulting path remains inside BASE_DIR;
  • raise ValueError for a path outside the directory;
  • when saving, create uploads/ if it does not exist yet.
load_file("notes.txt") -> OK
load_file("../secret.txt") -> rejected
save_file("../../outside.txt", "...") -> rejected

Úloha 8 — Bezpečnejšia serializáciaTask 8 — Safer Serialization

V tokens.py nahraďte pickle.loads() nad nedôveryhodnými dátami jednoduchým JSON spracovaním.

In tokens.py, replace pickle.loads() on untrusted data with simple JSON processing.

import json

def load_preferences(data: str) -> dict:
    value = json.loads(data)
    if not isinstance(value, dict):
        raise ValueError("Preferences must be a JSON object")
    return value

Požiadavky:

  • vstup nech je textový JSON, nie bytes pre pickle;
  • overte, že výsledok je dict;
  • povoľte iba očakávané kľúče, napríklad theme a language;
  • pri nevalidnom JSON vráťte zrozumiteľnú chybu.

Pointa nie je, že JSON je magicky bezpečný pre všetko. Pointa je nepúšťať nedôveryhodné dáta do mechanizmu, ktorý môže konštruovať Python objekty.

Requirements:

  • input should be textual JSON, not bytes for pickle;
  • verify that the result is a dict;
  • allow only expected keys, for example theme and language;
  • return a readable error for invalid JSON.

The point is not that JSON is magically safe for everything. The point is not to feed untrusted data into a mechanism that can construct Python objects.

Úloha 9 — Error handling a loggingTask 9 — Error Handling and Logging

Opravte app.py, aby nepoužíval prázdne except:.

Požiadavky:

  • zachytávajte konkrétne výnimky tam, kde viete zmysluplne reagovať;
  • chyby zapisujte cez logging;
  • používateľovi vypíšte stručnú zrozumiteľnú správu;
  • citlivé hodnoty, napríklad API key, nevypisujte do konzoly;
  • program nemá predstierať úspech, keď zlyhala kritická operácia.

Fix app.py so it does not use empty except: blocks.

Requirements:

  • catch concrete exceptions where you can respond meaningfully;
  • write errors through logging;
  • print a short readable message for the user;
  • do not print sensitive values, such as API keys, to the console;
  • the program should not pretend success when a critical operation failed.
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

ERROR: API_KEY is not configured

Úloha 10 — Bandit a finálny security checklistTask 10 — Bandit and Final Security Checklist

Spustite Bandit nad upraveným projektom.

Run Bandit on the modified project.

python -m bandit -r .

Potom pripravte krátky checklist, ktorý uvediete v README alebo v samostatnom security_notes.md.

Checklist má obsahovať:

  • aké problémy ste našli;
  • čo ste opravili;
  • ktoré riziká zostali a prečo;
  • ako ste overili SQL dotazy;
  • ako ste overili file path ochranu;
  • aké Bandit nálezy ostali relevantné alebo nerelevantné.

Then prepare a short checklist to include in README or a separate security_notes.md.

The checklist should include:

  • what issues you found;
  • what you fixed;
  • which risks remain and why;
  • how you verified SQL queries;
  • how you verified file path protection;
  • which Bandit findings remained relevant or irrelevant.
Security checklist
- SQL interpolation removed
- subprocess shell=True removed
- API key moved to environment
- path traversal rejected
- pickle replaced by JSON validation
- broad except removed

Bandit report nie je automaticky riešenie. Dôležité je, či rozumiete nálezom a viete vysvetliť svoje opravy.

A Bandit report is not automatically a solution. What matters is whether you understand the findings and can explain your fixes.
