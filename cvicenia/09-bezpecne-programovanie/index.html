Bezpečné programovanie v PythoneSecure Programming in Python

PrípravaSetup

Urobte obrannú revíziu lokálneho nástroja na registráciu dobrovoľníkov. Nástroj vyhľadáva prihlášky, číta prílohy, pripravuje menovky a vydáva pozvánky. Dodané dáta sú fiktívne a vybrané funkcie zámerne chybné. Používajte iba tento projekt a vlastné dočasné dáta; nejde o exportér reportov z prednášky.Perform a defensive review of a local volunteer registration tool. It searches applications, reads attachments, prepares badges and issues invitations. All supplied data are fictional and selected functions are deliberately flawed. Use only this project and temporary test data, not the lecture's report exporter.

CieleGoals

  • viazať opravu na konkrétny nežiaduci tok vstupuconnect each fix to a concrete unwanted input flow
  • zachovať legitímnu registráciu vrátane mien s apostrofompreserve legitimate registration including apostrophes in names
  • doložiť opravy testami a bezpečnou diagnostikoudemonstrate fixes with tests and safe diagnostics

ÚlohyTasks

Úloha 1 — Mapa dôvery a prvý testTask 1 — Trust map and first test

Najprv čítajte kód; app.py bez ďalších volieb iba ukazuje názvy operácií.Read the code first; app.py without options only lists operation names.

  • V security_notes.md označte vstupy, citlivé hodnoty a miesta, kde vstup ovplyvňuje SQL, proces, cestu alebo odpoveď.In security_notes.md identify inputs, sensitive values and where inputs affect SQL, processes, paths or output.
  • Pre každý nález uveďte konkrétny nežiaduci výsledok a jeden legitímny prípad, ktorý oprava musí zachovať.For each finding state a concrete unwanted outcome and a legitimate case the fix must preserve.
  • Vyberte prvý nález a pridajte zlyhávajúci regresný test nad lokálnymi dátami. Žiadne cudzie systémy netestujte.Choose the first finding and add a failing regression test with local data. Do not test external systems.

Úloha 2 — Validná prihláškaTask 2 — Valid volunteer application

Dobrovoľník zadáva meno, email a počet hodín, ktoré vie pomôcť.A volunteer provides a name, email and number of available hours.

  • Meno po úprave okrajových medzier má 1–80 znakov a môže obsahovať diakritiku, medzery aj apostrof.A trimmed name is 1–80 characters and permits accents, spaces and apostrophes.
  • Pre toto cvičenie email znamená reťazec do 200 znakov, jednu @, neprázdne obe strany a žiadne whitespace. Nejde o úplnú validáciu existencie adresy.For this exercise email means a string of at most 200 characters, exactly one @, nonempty parts and no whitespace. This does not verify that the address exists.
  • Počet hodín je presné celé číslo 1–40; bool, nekonečno a chybný text musia byť odmietnuté pred zápisom. Vymyslenou opravou nedopĺňajte neplatné hodnoty.Hours must be an actual integer in 1–40; reject booleans, infinity and malformed text before writing. Do not invent replacements for invalid input.

Úloha 3 — Vyhľadanie mena bez zmeny dotazuTask 3 — Name lookup without changing the query

Pripravte dočasnú databázu s aspoň troma fiktívnymi dobrovoľníkmi.Prepare a temporary database containing at least three fictional volunteers.

  • Vytvorenie aj vyhľadanie mena O'Neil musí fungovať bez zmeny verejného názvu a bez poškodenia tabuľky.Creating and looking up O'Neil must work without altering the name or damaging the table.
  • Vyhľadanie neznámeho mena vráti dohodnutý prázdny výsledok, nie iných používateľov.An unknown name returns the agreed empty result rather than other users.
  • Testy musia kontrolovať presné vrátené ID a nezmenený počet uložených záznamov. Nepripájajte skutočnú databázu.Tests must assert exact returned IDs and unchanged stored-record count. Do not use a real database.

Úloha 4 — Prístup k vlastnej príloheTask 4 — Access to an owned attachment

Dobrovoľník má čítať iba súbor pridelený jeho prihláške.A volunteer may read only the file assigned to their application.

  • Oddeľte identitu používateľa od ID prihlášky. Overeného používateľa v testoch dodá testovací kontext, nie ľubovoľný owner_id zo vstupu.Separate user identity from application ID. Tests supply verified identity through test context, not an arbitrary input owner_id.
  • Odmietnite prístup k cudzej prihláške aj odchod mimo uploads cez relatívnu alebo absolútnu cestu.Reject access to another user's application and relative or absolute paths escaping uploads.
  • Zachovajte čítanie pridelenej welcome.txt a opíšte predpoklad, kto smie meniť obsah uploads a symlinky.Preserve access to an assigned welcome.txt and document who may modify uploads and symlinks.

Úloha 5 — Menovka ako dáta, nie príkazTask 5 — Badge data, not a command

commands.py spúšťa lokálny badge_worker.py; nepotrebujete ping, sieť ani systémový konvertor.commands.py launches the local badge_worker.py; no ping, network or system converter is required.

  • Meno s apostrofom, medzerou alebo bodkočiarkou sa má dostať do worker-a ako jediný dátový argument.A name containing an apostrophe, space or semicolon must reach the worker as one data argument.
  • Spúšťaný program vyberá aplikácia. Vstup nesmie pridať ďalší proces alebo meniť voľby aplikácie.The application selects the executable. Input must not add another process or change application options.
  • Neúspešný worker aj prekročenie času majú konkrétny výsledok. Test overí prijaté meno a vykoná sa iba nad vlastným worker-om.A failed worker and timeout must have explicit outcomes. Test the received name using only the supplied worker.

Úloha 6 — Pozvánka s obmedzenou platnosťouTask 6 — An invitation with bounded validity

Pozvánka je citlivý jednorazový údaj, nie šesťciferný verejný identifikátor.An invitation is a sensitive single-use value, not a public six-digit identifier.

  • Vytvorte nepredvídateľné pozvánky a uložte iba údaje potrebné na ich overenie. Samotnú hodnotu neuvádzajte v bežnom logu.Generate unpredictable invitations and store only what is needed to verify them. Do not include the raw value in routine logs.
  • Pozvánka patrí jednému dobrovoľníkovi, platí 15 minút a po použití sa nedá použiť znova. Čas v testoch musí byť kontrolovaný.An invitation belongs to one volunteer, expires after 15 minutes and is single-use. Tests must control time.
  • Overte platný token, nesprávny token, iného vlastníka, hranicu vypršania a opakované použitie. Úspech nesmie závisieť od čakania reálnych 15 minút.Test valid and invalid tokens, wrong ownership, the expiry boundary and reuse without waiting 15 real minutes.

Úloha 7 — Nastavenia sú dátový dokumentTask 7 — Preferences are a data document

Používateľ importuje nastavenia menovky. Použite iba dodaný neškodný JSON a vlastné textové prípady.A user imports badge preferences. Use only the supplied harmless JSON and your own text cases.

  • Podporujte len objekt s theme light/dark a language sk/en; cudzie kľúče, iný typ, priveľký vstup nad 4096 bajtov a neplatné hodnoty odmietnite.Accept only an object with theme light/dark and language sk/en. Reject unknown keys, other types, input over 4096 bytes and invalid values.
  • Import nesmie vykonať kód. Nevytvárajte škodlivý pickle; vysvetlite problém pôvodného loadera a nahraďte kontrakt dátovým formátom.Import must not execute code. Do not create a malicious pickle; explain the original loader's risk and replace it with a data-format contract.
  • Pri chybe ostanú predošlé platné nastavenia zachované. Testujte aj prázdny dokument a JSON zoznam namiesto objektu.Keep previous valid preferences on failure. Test an empty document and a JSON array instead of an object.

Úloha 8 — Konfigurácia a súkromie výpisuTask 8 — Configuration and output privacy

Aplikácia má prístupový kľúč k fiktívnej službe pozvánok. Na cvičení sa nikam nepripája.The application has a key for a fictional invitation service; the exercise never connects to it.

  • Reálny kľúč nesmie byť v source code, commite, tracebacku pre používateľa ani v logu. Pripravte iba neškodnú .env.example a ignorovanie lokálnej konfigurácie.A real key must not appear in source, commits, user-facing tracebacks or logs. Provide only a harmless .env.example and ignore local configuration.
  • Chýbajúca konfigurácia má čitateľné hlásenie. V README vysvetlite, či a ako sa lokálny .env vôbec načítava.Missing configuration needs a clear message. Explain whether and how a local .env is loaded.
  • Testu dodajte unikátny fiktívny kľúč a token a potvrďte, že sa nenachádzajú v zachytenom stdout, stderr ani logu.Supply unique fake key and token values in tests and assert they are absent from captured stdout, stderr and logs.

Úloha 9 — Chybové stavy sa nestratiaTask 9 — Errors remain observable

Namiesto univerzálneho tichého úspechu musí nástroj rozlišovať očakávané neúspechy.The tool must distinguish expected failures rather than reporting silent universal success.

  • Odlíšte chybný vstup, nedostupnú prílohu, odmietnutý prístup a zlyhanie worker-a. Definujte ich výsledok pre volajúceho.Distinguish invalid input, missing attachment, denied access and worker failure. Define the outcome for callers.
  • Neočekávanú programátorskú chybu nezamaskujte ako úspech. Diagnostika môže obsahovať operáciu a bezpečné ID, nie celé prihlášky a tajomstvá.Do not disguise unexpected programming errors as success. Diagnostics may include an operation and safe ID, not complete applications or secrets.
  • Pri neúspešnom importe sa nesmie zmeniť databáza ani nastavenia. Overte to testom porovnávajúcim stav pred operáciou a po nej.A failed import must not change database or preferences. Compare before/after state in a test.

Úloha 10 — Revízia doložená správanímTask 10 — Behaviour-backed review

Uzavrite revíziu tak, aby bolo vidieť opravu aj jej hranice.Finish with evidence of each fix and its limits.

  • Odovzdajte aspoň osem regresných testov, ktoré spolu pokrývajú každú upravenú hranicu a aspoň dva legitímne prípady.Deliver at least eight regression tests covering every modified boundary and at least two legitimate cases.
  • Spustite pomocný statický audit a pri každom zostávajúcom náleze napíšte rozhodnutie a dôvod; výsledok nástroja nie je jediným dôkazom.Run a supporting static audit and justify each remaining finding. Tool output alone is not proof.
  • Doplňte mapu nález → oprava → test, presný postup spustenia a informáciu, čo by sa pri skutočnom úniku kľúča muselo urobiť.Provide a finding → fix → test map, exact run instructions and the response required for a real key leak.

OdovzdanieDeliverables

  • Opravené moduly, izolované testy a security_notes.md. Nedodávajte skutočné heslá, tokeny, osobné údaje ani pracovnú databázu.Deliver fixed modules, isolated tests and security_notes.md, without real secrets, personal data or a working database.
