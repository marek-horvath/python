Znenie zadaniaAssignment

Navrhnite a implementujte vlastný softvérový projekt v jazyku Python. Tému projektu si volíte sami. Projekt musí riešiť konkrétny problém alebo poskytovať ucelenú funkcionalitu a musí vhodným spôsobom využívať viacero oblastí preberaných počas predmetu.Design and implement your own software project in Python. You choose the topic yourself. The project must solve a concrete problem or provide coherent functionality and must meaningfully use several areas covered during the course.

Výsledkom musí byť funkčný a spustiteľný projekt, ku ktorému odovzdáte zdrojový kód, technickú dokumentáciu vo formáte PDF a približne 5-minútovú videoprezentáciu.The result must be a functional, runnable project submitted with source code, technical documentation in PDF format and an approximately 5-minute video presentation.

CieleGoals

  1. Navrhnúť a implementovať vlastný Python projekt.Design and implement an individual Python project.
  2. Prakticky využiť viacero tém a technológií predstavených počas semestra.Apply several topics and technologies covered during the semester.
  3. Rozdeliť väčší problém na menšie moduly a komponenty.Break a larger problem into smaller modules and components.
  4. Dodržiavať základné programátorské best practices primerané rozsahu projektu.Follow basic programming best practices appropriate for the project scope.
  5. Dokumentovať návrh, implementáciu a spôsob používania vlastného riešenia.Document the design, implementation and usage of the solution.
  6. Prezentovať funkčnosť a technické riešenie projektu.Present the functionality and the technical solution.

Čo nie je dostatočný projektWhat Is Not Sufficient

Za dostatočný semestrálny projekt sa nepovažuje samotný:The following by itself is not considered sufficient for a semester project:

  • samotný kalkulátor alebo jednoduchý prevodník jednotieka standalone calculator or a simple unit converter
  • program pozostávajúci z niekoľkých input/print operáciía program made of a few input/print operations
  • jedna statická webová stránkaa single static web page
  • jednoduchý CRUD nad jednou tabuľkou bez ďalšej logikya simple CRUD interface over one table without additional logic
  • jeden notebook, ktorý iba načíta CSV a vytvorí jeden grafone notebook that only loads a CSV file and creates one chart
  • script s niekoľkými príkazmi bez vlastnej aplikačnej logikya script with a few commands and no meaningful application logic

Splnenie minimálnych technických podmienok samo osebe nezaručuje plný počet bodov.Meeting the minimum technical requirements alone does not guarantee full points.

Kvalitatívne požiadavkyQuality Requirements

Tieto veci nie sú samostatné technologické moduly, ale základná kvalita každého projektu. Hodnotí sa primeranosť riešenia vzhľadom na typ projektu.These are not separate technology modules, but baseline quality expectations for every project. Evaluation considers what is appropriate for the project type.

  • modularitu a rozumnú štruktúru projektumodularity and a reasonable project structure
  • error handling a validáciu vstupoverror handling and input validation
  • konfiguráciu oddelenú od aplikačnej logikyconfiguration separated from application logic
  • testovanie primerané typu projektutesting appropriate for the project type
  • bezpečné programovanie, čitateľnosť kódu a správu dependenciessecure programming, code readability and dependency management
  • technickú dokumentáciu a priebežnú prácu v Gittechnical documentation and continuous work with Git

Programátorský štýl a best practicesProgramming Style and Best Practices

  • Nepíšte celý projekt do jedného `main.py`, ak na to nie je dobrý dôvod.Do not put the entire project into one `main.py` unless there is a good reason.
  • Rozdeľte riešenie do logických modulov a používajte funkcie alebo triedy tam, kde dávajú zmysel.Split the solution into logical modules and use functions or classes where they make sense.
  • Pomenujte premenné, funkcie, triedy a moduly tak, aby vyjadrovali ich účel.Name variables, functions, classes and modules so their purpose is clear.
  • Minimalizujte duplicitu a oddeľte používateľské rozhranie od aplikačnej logiky, ak je to relevantné.Minimize duplication and separate the user interface from application logic where relevant.
  • Používajte type hints aspoň na dôležitých častiach vlastného API.Use type hints at least on the important parts of your own API.
  • Nepoužívajte `except: pass` a nereagujte na chyby tichým ignorovaním.Do not use `except: pass` and do not silently ignore errors.
  • Nehardcodujte absolútne cesty, heslá, API keys ani secrets do source code.Do not hardcode absolute paths, passwords, API keys or secrets in source code.
  • Pri SQL používajte parameterized queries.Use parameterized queries for SQL.
  • Git používajte priebežne, nie jedným commitom na konci.Use Git continuously, not as one final commit at the end.

Každé riešenie nemusí používať OOP. Python projekt môže byť kvalitne modulárny aj pomocou funkcií. Architektúra má zodpovedať problému.Not every solution has to use OOP. A Python project can be well structured using functions. The architecture should match the problem.

SpustiteľnosťRun Instructions

Projekt musí byť možné spustiť aj na inom počítači podľa README. Nesmie fungovať iba vďaka hardcoded adresárom, ručne vytvorenej databáze mimo projektu, chýbajúcim assets, neuvedeným dependencies alebo secretom uloženým iba v IDE.The project must be runnable on another computer using the README. It must not work only because of hardcoded paths, a manually created database outside the project, missing assets, undocumented dependencies or secrets stored only in an IDE.

Milestone 1 — MVP

6. týždeň semestra · 30 bodovWeek 6 · 30 points

MVP je prvá funkčná verzia projektu, na ktorej už musí byť viditeľná hlavná myšlienka aplikácie a základ technického riešenia. Nie je to iba PDF s návrhom. Musí existovať reálny kód a spustiteľná časť projektu.The MVP is the first functional version of the project where the main idea and the basis of the technical solution are already visible. It is not just a design PDF. Real code and a runnable part of the project must exist.

  • definovaný problém, téma a cieľ projektudefined problem, topic and project goal
  • základná architektúra a vytvorený Git repositorybasic architecture and an initialized Git repository
  • rozbehnutý projekt so spustiteľnou základnou funkcionalitoustarted project with runnable core functionality
  • minimálne 3 plánované technologické oblasti a dôvod ich použitiaat least 3 planned technology areas and a reason for using them
  • plán toho, čo zostáva do finálnej verzieplan for what remains before the final version

Zmena projektu po MVPChanging the Project after the MVP

Po MVP je možné projekt primerane upraviť alebo zmeniť jeho rozsah. Výrazná zmena témy však nesmie slúžiť na obídenie hodnotenia MVP a študent by mal vedieť vysvetliť, prečo návrh zmenil.After the MVP, the project may be adjusted or its scope may change reasonably. A major topic change must not be used to bypass MVP grading, and the student should be able to explain why the change was made.

The recommended length is about 10–15 pages. The document should not be artificially padded; use images, diagrams and snippets where they help explain the solution.

Samostatnosť a zdrojeIndependent Work and Sources

Projekt musí byť výsledkom vlastnej práce študenta. Je možné používať dokumentáciu, knihy, Stack Overflow, tutoriály, AI nástroje a bežné vývojárske zdroje, ale študent musí rozumieť výslednému riešeniu a vedieť vysvetliť svoje technické rozhodnutia.The project must be the student's own work. Documentation, books, Stack Overflow, tutorials, AI tools and common developer resources may be used, but the student must understand the submitted solution and be able to explain technical decisions.

Nie je v poriadku odovzdať cudzí alebo kompletne prevzatý projekt ako vlastný. Výraznejší externý zdroj, template, knižnica alebo AI nástroj má byť transparentne uvedený v dokumentácii spolu s tým, na čo bol použitý.Submitting someone else's project or a fully copied project as your own is not acceptable. Significant external sources, templates, libraries or AI tools should be transparently listed in the documentation together with how they were used.
